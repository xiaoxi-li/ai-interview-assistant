## 1. 项目背景与目标

为求职者在远程面试场景中提供两大核心能力：

1. **知识库**：Markdown 笔记的导入、编辑、维护、群组管理，以及全文/语义检索。
2. **面试辅助**：实时捕获面试官语音 → 流式转文字 → 检索知识库 → 结合 AI 生成回答。

设计原则：本地优先、低资源占用、低延迟、隐私可控、双平台一致。

## 3. IA-13 迷你模式（变更迭代）

### 3.1 背景与现状问题

**现状实现**：面试页右上角提供「缩小」按钮，点击后由后端 `open_mini_window` 创建一个独立第二 WebView 窗口（标签 `mini`，无边框、置顶、跳过任务栏）来渲染精简视图 `MiniView`。

**缺陷（用户实测反馈）**：

- 点击「缩小」后弹出的方框**内容空白**；
- 方框**无响应**（无法拖动）；
- **无法关闭**（无系统标题栏，也无可点击的关闭入口），只能借助任务管理器或 Alt+F4 强退，形成体验死锁。

**根因分析**：该窗口以 `decorations(false)` 创建，即完全依赖 WebView 内部渲染的自定义标题栏（含 `data-tauri-drag-region` 拖动区与关闭按钮）提供全部交互。一旦第二 WebView 的内容未能成功渲染（第二个 WebView 独立加载完整前端入口 `index.html`，其初始化链路与主窗口不同且未经过主窗口同等的启动校验），窗口就退化为「无内容 + 无拖动区 + 无关闭按钮」的空白方框，用户失去所有恢复手段。

**结论**：第二窗口方案把「界面可用性」与「第二个 WebView 的渲染成功」强绑定，失败模式不可恢复，属于结构性风险，需要改为不依赖第二 WebView 的实现。

### 3.2 变更后的需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| IA-13.1 | 点击「缩小」后，**当前整个界面就地切换**为迷你页：仅展示「当前面试官问题」与「AI 回答」（含引用来源） | P0 |
| IA-13.2 | 进入迷你模式时，主窗口自动收缩为小尺寸浮窗（约 420×340，最小 320×200）并置顶 | P0 |
| IA-13.3 | 迷你页提供「恢复」按钮：一键还原完整界面，并还原进入前的窗口尺寸、位置与置顶状态 | P0 |
| IA-13.4 | 迷你页提供「退出应用」按钮：直接关闭应用（遵循设置中的托盘行为配置） | P0 |
| IA-13.5 | 标题栏「缩小」按钮、应用内/全局热键 `Ctrl+Shift+M`、托盘菜单「迷你模式」三处入口语义一致，均为「就地切换」 | P0 |
| IA-13.6 | 迷你模式下保持面试链路能力：热键、问题/回答实时推送、最近问答恢复均正常工作 | P0 |
| IA-13.7 | 移除独立迷你窗口相关实现（后端命令、前端封装、窗口 ACL 绑定、mock 与测试），不留无效代码路径 | P1 |
| IA-13.8 | 迷你模式状态不持久化（会话内有效），应用重启后回到完整界面 | P1 |

### 3.3 场景与用例

**主场景：面试进行中需缩小窗口规避被面试官看到全屏**

1. 用户正在面试辅助页，面试官提问已被识别，AI 回答正在流式输出。
2. 用户点击标题栏「缩小」按钮（或按 `Ctrl+Shift+M`）。
3. 界面立即切换为迷你页：上方显示当前问题，下方显示 AI 回答（继续流式追加）。
4. 窗口收缩为小尺寸并置顶，用户可将其拖到屏幕角落。
5. 面试结束后，用户点击「恢复」，界面回到面试辅助页，窗口还原为进入前的尺寸与位置。

**备选用例**

- 热键切换：面试中按 `Ctrl+Shift+M` 进入迷你模式，再按一次恢复（切换语义）。
- 托盘入口：应用隐藏到托盘后，从托盘菜单选择「迷你模式」→ 主窗口显示并进入迷你模式。
- 无会话数据：迷你页显示「等待识别面试官问题…」与「识别到问题后这里会显示 AI 回答」占位提示。
- 生成失败：迷你页在回答区展示错误信息（如「尚未配置 API Key」）。
- 恢复后回到面试页：无论进入迷你模式前位于哪个页面，恢复后统一回到「面试辅助」页（减少一次手动切换，符合面试场景）。

### 3.4 交互与视觉约束

- 迷你页顶部为可拖动的窄标题栏（应用名 + 迷你标识），右侧为「恢复」「退出应用」两个图标按钮。
- 主体自上而下：「当前问题」卡片、「AI 回答」卡片（流式光标 / 生成中占位 / 错误提示）、引用来源标签。
- 适配约 420×340 小窗：内容可滚动，最小尺寸 320×200 下不溢出、不换行错乱。
- 风格沿用现有深色卡片体系（Tailwind 现有色板、圆角、字号）。
- 「退出应用」按钮采用危险色（hover 红色）以区分于「恢复」。

### 3.5 边界场景

| 场景 | 期望行为 |
|---|---|
| 重复点击「缩小」 | 幂等：已处于迷你模式时不重复记录窗口快照，仅确保尺寸与置顶生效 |
| 进入迷你模式时窗口处于最大化 | 先取消最大化，退出时若原为最大化则恢复最大化 |
| 进入前窗口本身已置顶（设置中开启） | 退出后仍保持置顶；未开启则退出后取消置顶 |
| 非 Tauri 环境（浏览器内开发/单测） | 命令调用安全降级为无操作，UI 状态仍可切换，保证测试可运行 |
| 关闭应用时处于迷你模式 | 遵循托盘行为配置：可能最小化到托盘，也可能直接退出；行为与标题栏「关闭」一致 |
| 迷你模式下从托盘唤出主窗口 | 仍保持迷你状态（状态为会话内有效，不因隐藏/显示而丢失） |

### 3.6 验收标准

1. 点击「缩小」不再产生任何新的空白窗口；界面直接切换为迷你页，1 秒内可见当前问题与回答。
2. 迷你页内容正常显示（问题、回答、引用、占位、错误态），文字可滚动，无空白。
3. 迷你页「恢复」按钮点击后回到完整界面，且窗口尺寸/位置/置顶状态与进入前一致（容差：±1px）。
4. 迷你页「退出应用」按钮可正常关闭应用（或按配置最小化到托盘），不存在无法关闭的窗口。
5. `Ctrl+Shift+M` 可双向切换迷你模式；托盘「迷你模式」菜单项可进入迷你模式。
6. 迷你模式下：流式回答继续追加、「重新生成」等热键仍生效、最近问答在进入时正确恢复。
7. 代码中不再存在 `open_mini_window` / `close_mini_window` / `mini_window_open` / `mini` 窗口相关引用。
8. `npm run verify` 与 `cargo test` 全部通过。
