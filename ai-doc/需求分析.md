## 2. 产品概述

### 2.1 背景与痛点

远程/线上面试已成主流，求职者在实时对话中面临三类痛点：

| 痛点 | 具体表现 |
|---|---|
| 听不清/记不住 | 面试官问题长、专业名词密集，紧张时容易漏听或记错 |
| 资料找不到 | 自己的笔记与项目总结散落各处，面试当场无法快速检索 |
| 回答组织慢 | 需要在几十秒内组织结构化回答，临场发挥不稳定 |

同时面试内容高度敏感，**求职者对「音频/笔记是否上传云端」极为在意**，这是必须正面回应的约束。

### 2.2 定位与两大能力

> **一句话定位**：一款本地优先的桌面端面试辅助工具 —— 边听面试官提问，边把「问题 + 知识库参考 + AI 回答」实时呈现在你眼前。

1. **知识库**：Markdown 笔记的导入、编辑、组织与中文全文/语义检索；
2. **面试辅助**：实时采集音频 → 流式转写 → 问题识别 → 检索自己的笔记 → AI 生成参考回答。

设计原则：**本地优先、低资源占用、低延迟、隐私可控、双平台一致**。

### 2.3 目标用户与画像

| 画像 | 特征 | 核心诉求 | 关键场景 |
|---|---|---|---|
| **主要：技术岗求职者** | 有 Markdown 笔记习惯，远程面试频繁 | 面试中秒级拿到「自己的答案」，且不泄露隐私 | 一对一技术面、系统设计面 |
| **次要：非技术岗求职者** | 笔记以经验/案例为主，术语少 | 结构化回答框架、避免冷场 | 行为面、HR 面 |
| **边缘：面试练习者** | 自测/模拟面试 | 复盘自己的回答与表达 | 录音回放 + 笔记对照 |

### 2.4 核心价值

1. **用自己的知识回答**：回答基于用户自己的笔记召回，而非通用模型凭空生成；
2. **隐私默认最优**：P0 阶段音频不出本机（仅本地 ASR 通路），笔记与会话数据默认本地存储；
3. **零门槛验证**：内置「一键演示」可在无麦克风、无模型、无 API Key 的条件下跑通全链路；
4. **轻量常驻**：安装包小、空闲内存低，可长时间挂在后台随时开面。

### 2.5 成功度量（目标值，非承诺）

| 维度 | 目标 |
|---|---|
| 检索延迟（客户端） | < 200ms |
| AI 首 token（端到端，依赖服务商） | < 2s |
| 面试中可感知的辅助 | 面试官话音结束后数秒内出现「问题 + 参考 + 回答」 |
| 数据安全性 | 默认状态下音频与笔记不出本机 |

## 3. 术语与缩略语

| 术语 | 说明 |
|---|---|
| KB / IA / ST / SYS | 需求模块前缀：知识库 / 面试辅助 / 设置 / 系统级 |
| ASR | 自动语音识别（语音转文字） |
| VAD | 语音活动检测，用于静音过滤与自动分段 |
| AEC | 回声消除，防止扬声器声音被麦克风重复采集 |
| partial / final | 转写中间结果 / 段结束确认结果（final 即落库） |
| 双通道 | 麦克风=「我」、系统音频=「面试官」的两路并行采集，用于近似说话人区分 |
| 分块（chunk） | 笔记按 token 切分后的检索单元，默认 512 token、重叠 50 |
| 混合检索 | 关键词（FTS5/BM25）+ 向量（语义）双路召回后融合排序 |
| RRF | Reciprocal Rank Fusion，多路召回的融合排序算法 |
| 隐身模式 | 窗口置顶 + 防录屏保护 + 托盘常驻，降低被屏幕共享捕获的风险 |
| 迷你模式 | 应用内就地切换为「仅问题 + 回答」的迷你页，主窗口同时缩为置顶小窗 |
| 本地优先 | 数据在默认配置下全部留在本机，云端能力需显式开启 |
| 客户端预算 / 端到端目标 | 前者本地可控、作为验收项；后者依赖外部网络与服务商，仅监控打点 |

## 4. 业务场景与用例

### 4.1 典型场景

> **场景 A（核心）**：小李参加远程技术面，打开应用进入「面试辅助」页开启采集。
> 面试官提问 → 转写面板实时出现文字（先斜体 partial，后 final 落库）→ 系统识别问题并给出置信度
> → 从他导入的 30 篇笔记中召回 3 段参考 → AI 基于参考流式生成回答 → 他扫一眼即可作答。
> 面试结束后在「会话历史」回放时间线并导出 Markdown 复盘。

> **场景 B（准备）**：面试前一天批量导入 Markdown 笔记，按「后端/项目/八股」建群组，搜索「缓存击穿」验证中文检索与语义召回。

> **场景 C（隐私顾虑）**：小王担心录音外泄，在向导中选择本地 ASR 通路；面试中开启隐身模式，避免窗口内容被屏幕共享/录屏捕获。

> **场景 D（规避视线）**：面试中需要把界面缩到角落，点标题栏「缩小」（或 `Ctrl+Shift+M`）就地切换迷你模式，结束后点「恢复」还原。

| 异常 | 期望行为 | 关联需求 |
|---|---|---|
| 未授权麦克风 / 屏幕录制（macOS） | 首次向导明确告知受限范围，不静默失败 | SYS-01 |

## 5. 功能需求（FR）

> 状态图例：✅ 已交付 ｜ ⚠️ 部分交付（存在已知限制）｜ ⬜ 规划中

### 5.1 知识库模块（KB）

**KB-01 Markdown 导入**（P0 · ✅）
- 需求：支持单文件导入、文件夹批量导入、拖拽导入。
- 验收：① 拖拽含子目录的文件夹后，笔记数量与 Markdown 文件数一致；② 重复导入不产生重复笔记；③ 单个文件失败有明确提示且不影响其余文件。

**KB-02 Markdown 编辑**（P0 · ✅）
- 需求：源码 / 预览双视图，支持语法高亮、表格、任务列表、代码块、图片渲染。
- 验收：① 双视图切换不丢内容；② 表格、代码块、任务列表渲染正确；③ 编辑后自动保存并可被检索到。

**KB-03 笔记维护**（P0 · ✅）
- 需求：新建、重命名、删除、移动；删除进入回收站，支持恢复与彻底清空。
- 验收：① 删除后在回收站可见并可恢复；② 清空回收站有二次确认；③ 移动后群组归属正确。

**KB-04 群组管理**（P0 · ✅）
- 需求：多级群组、拖拽排序、批量移动。
- 验收：① 支持二级以上嵌套；② 拖拽顺序持久化，重启后保持；③ 批量移动后归属正确。

**KB-05 标签系统**（P1 · ✅ 已提前交付）
- 需求：为笔记打标签、按标签筛选。
- 验收：① 标签增删改即时生效；② 按标签筛选结果正确；③ 标签参与全文检索字段。

**KB-06 中文全文检索**（P0 · ✅）
- 需求：基于 SQLite FTS5 + jieba 中文预分词，覆盖标题 / 正文 / 标签。
- 验收：① 中文长句查询（如「缓存击穿怎么解决」）能命中相关笔记（FTS5 默认分词对中文无效，必须预分词）；② 结果按 BM25 相关性排序；③ 检索响应 < 200ms。

**KB-07 向量（语义）检索**（P0 · ⚠️）
- 需求：笔记分块后生成嵌入向量，支持语义相似度召回；向量库抽象为 `VectorStore` 以便替换实现。
- 验收：① 同义/近义表述也能召回；② 新笔记写入后自动增量建索引；③ 向量不可用时**降级为纯关键词检索并明确提示**。
- 已知限制：本地 ONNX 推理尚未接入，当前为确定性 Mock 嵌入；向量维度已迁移至 1024（bge-m3）。

**KB-08 混合检索与融合排序**（P1 · ✅）
- 需求：BM25 与向量双路召回后融合排序（RRF），分块大小/重叠等参数可配置。
- 验收：① 融合结果优于或至少不退化为单路检索；② 融合得分与来源（关键词/语义）在 UI 上可解释；③ 参数调整后重建索引生效。

**KB-09 版本历史**（P2 · ✅ 已提前交付）
- 需求：保留笔记最近 N 个版本，可查看与回滚。
- 验收：① 每次保存生成快照；② 回滚后内容与所选版本一致；③ 版本数量受配置上限约束。

**KB-10 导出与备份**（P1 · ✅）
- 需求：导出 Markdown / JSON，支持整库备份与恢复。
- 验收：① 导出文件可被外部工具正常打开；② 备份恢复后笔记、群组、标签、索引完整；③ 恢复前提示覆盖风险。

### 5.2 面试辅助模块（IA）

**IA-01 实时音频捕获（双路）**（P0 · ✅）
- 需求：同时采集麦克风与系统音频（Windows WASAPI loopback / macOS ScreenCaptureKit）。
- 验收：① 两路设备可分别选择与切换；② 启动/停止状态在 UI 明确可见；③ 16kHz 单声道 20ms 帧稳定输出。

**IA-02 回声消除（AEC）**（P1 · ✅ 已提前交付）
- 需求：抑制扬声器声音被麦克风重复采集，含双讲检测。
- 验收：① 播放参考音频时麦克风通道残差明显下降；② 双方同时说话时不误抑制；③ 可在设置中开关。

**IA-03 VAD 语音活动检测**（P0 · ✅）
- 需求：静音过滤与自动分段，减少无效音频。
- 验收：① 静音段不产生转写文本；② 语句间停顿能正确切段；③ 阈值可配置。

**IA-04 实时 ASR 流式转写**（P0 · ⚠️）
- 需求：本地引擎流式转写，输出 partial / final；final 实时落库。
- 验收：① partial 先出现、随后被 final 覆盖；② final 段落写入数据库，重启/崩溃后仍可回放；③ 端到端延迟满足目标（< 1s，依赖本机算力与模型）。
- 已知限制：native 推理未接入 —— `SherpaOnnxEngine::transcribe_segment` 显式返回错误（宁可不出文本，也不伪造）。

**IA-05 说话人区分**（P1 · ✅ 已提前交付）
- 需求：区分「我」与「面试官」，转写面板分色展示。
- 验收：① 双通道并行采集时归属正确；② UI 上视觉可辨；③ 可在单通道与双通道模式间切换。

**IA-06 问题识别**（P0 · ✅）
- 需求：从转写流中识别面试官问题，支持自动与快捷键触发，给出置信度与命中信号。
- 验收：① 疑问句式被识别；② 相邻重复问题自动去重；③ 展示置信度徽标与命中信号 chips。

**IA-07 知识库检索召回**（P0 · ✅，质量受 KB-07 限制）
- 需求：按识别到的问题召回相关笔记片段（标题 + 摘要 + 融合得分）。
- 验收：① 每个问题下方展示召回片段；② 与知识库检索共用同一实现；③ 无命中时明确提示而非空白。

**IA-08 AI 回答生成（流式）**（P0 · ✅）
- 需求：结合召回结果调用 AI Provider，SSE 流式输出（打字机效果），含超时与重试。
- 验收：① token 逐字流出，标题显示所用模型；② 未配置 Key 时使用离线回答并**显式标注「离线演示回答」**；③ 网络/鉴权失败有明确错误提示。

**IA-09 回答引用来源**（P1 · ✅ 已提前交付）
- 需求：回答下方展示参考了哪些笔记，可点击跳转并定位。
- 验收：① 引用列表与召回来源一致；② 点击跳转后定位到对应笔记；③ 无引用时不显示空列表。

**IA-10 面试会话记录**（P1 · ✅；转写落库已提前至 P0）
- 需求：会话浏览 / 时间线回放 / 导出 Markdown 与 JSON / 删除。
- 验收：① 时间线包含转写、问答、引用；② 导出文件内容完整、格式正确；③ 删除会话级联清理其转写与问答。

**IA-11 隐身模式**（P0 · ⚠️）
- 需求：窗口置顶、防录屏保护（`set_content_protected`）、托盘常驻、全局快捷键。
- 验收：① 开启后置顶且屏幕共享/录屏中不可见内容；② 托盘图标可唤起；③ 全局快捷键在应用失焦时仍生效。
- 已知限制：开关目前仅在面试页快捷条，尚未同步到「设置 → 界面」表单。

**IA-12 快捷操作**（P0 · ✅）
- 需求：一键提问、重新生成、复制回答、暂停/继续采集。
- 验收：① 四个操作均可由界面与快捷键触发；② 暂停期间丢弃音频帧但保留会话与记录；③ 快捷键可修改。

**IA-13 迷你模式**（P0 · ✅）

> 变更背景：早期实现为**创建独立第二 WebView 小窗**（标签 `mini`、无边框）。实测出现「空白方框 + 无法拖动 + 无法关闭」的体验死锁 —— 无边框窗口的全部交互依赖第二个 WebView 成功渲染，失败模式不可恢复。
> 变更决策：**改为应用内就地切换**，主窗口同步缩为置顶小窗，不引入第二窗口。

| 编号 | 需求 | 优先级 |
|---|---|---|
| IA-13.1 | 点击「缩小」后**当前整个界面就地切换**为迷你页：仅展示当前面试官问题与 AI 回答（含引用来源） | P0 |
| IA-13.2 | 进入时主窗口自动收缩为小尺寸浮窗（约 420×340，最小 320×200）并置顶 | P0 |
| IA-13.3 | 迷你页提供「恢复」：还原完整界面，并还原进入前的窗口尺寸、位置与置顶状态 | P0 |
| IA-13.4 | 迷你页提供「退出应用」：直接关闭应用（遵循设置的托盘行为配置） | P0 |
| IA-13.5 | 标题栏「缩小」按钮、应用内/全局热键 `Ctrl+Shift+M`、托盘菜单三处入口语义一致 | P0 |
| IA-13.6 | 迷你模式下保持面试链路能力：热键、问题/回答实时推送、最近问答恢复正常 | P0 |
| IA-13.7 | 移除独立迷你窗口相关实现（命令、前端封装、窗口 ACL、mock 与测试），不留无效代码路径 | P1 |
| IA-13.8 | 迷你模式状态不持久化（会话内有效），重启后回到完整界面 | P1 |

- 交互约束：① 迷你页顶部为可拖动窄标题栏 +「恢复」「退出应用」两个图标按钮；② 主体为「当前问题」卡片 +「AI 回答」卡片（流式光标/占位/错误态）+ 引用来源；③ 适配 420×340，最小 320×200 不溢出；④ 「退出应用」用危险色区分；⑤ 恢复后统一回到面试辅助页。
- 边界场景：① 重复点击「缩小」幂等，不重复记录快照；② 进入时若最大化则先取消，退出时恢复最大化；③ 进入前已置顶则退出后仍置顶；④ 非 Tauri 环境命令安全降级为空操作，UI 仍可切换；⑤ 迷你模式下从托盘唤出仍保持迷你状态；⑥ 后端窗口调整失败时回退视图状态。
- 验收：① 不再产生任何新的空白窗口，1 秒内可见问题与回答；② 迷你页内容正常且可滚动；③ 「恢复」后窗口尺寸/位置/置顶与进入前一致（±1px）；④ 「退出应用」可正常关闭或最小化到托盘；⑤ `Ctrl+Shift+M` 双向切换、托盘入口可进入；⑥ 迷你模式下流式回答与热键仍生效；⑦ 代码中不再有 `open_mini_window` / `close_mini_window` / `mini_window_open` / `mini` 窗口引用；⑧ `npm run verify` 与 `cargo test` 通过。

## 9. 约束、假设与依赖

### 9.1 约束
1. **隐私优先**：P0 只做本地 ASR 通路，云端多厂商（讯飞/阿里/腾讯）协议适配延至 P1；配置项与凭证管理保留。
2. **体积约束**：安装包口径为「主程序 < 20MB，不含 ONNX Runtime 动态库与模型」；模型一律按需下载。
3. **平台差异**：macOS 系统音频依赖屏幕录制授权；Windows 依赖 WebView2 与 WASAPI loopback。
4. **交互可靠性**：不引入「一旦渲染失败即不可恢复」的窗口形态（IA-13 的硬约束）。
5. **合规**：隐身/防录屏能力需谨慎定位与说明。

### 9.2 假设
1. 用户具备可用的音频输入设备与稳定网络（AI 回答需联网）。
2. 用户愿意为语义检索下载较大体积的嵌入模型（约 2.27GB），或接受降级为关键词检索。
3. 面试场景以中文为主，中文分词与中文嵌入模型优先级最高。

### 9.3 依赖
1. 第三方模型文件（bge-m3 / silero-vad / sherpa-onnx paraformer）的可获取性与完整性（SHA256）。
2. AI 服务商接口稳定性、配额与账号有效性。
3. 双平台 CI（GitHub Actions Windows / macOS runner）可用性。

## 11. 验收与测试策略

1. **主验收路径 = 一键演示**：无需麦克风、模型、API Key，按 `README.md` 第三节清单逐项确认。演示只替换输入源、不替换业务逻辑（问题识别、召回、落库、事件、回放均为真实实现；仅「音频 → 文本」由脚本提供）。
2. **测试分层**：前端 Vitest（`npm run verify`）；Rust 单测 + PCM 回放集成测试（`cargo test`）；手工验收（演示清单 + 安装包 + 设置项保存）；双平台 CI。
3. **验收原则**：① 每条 FR 的验收条目可直接转化为测试用例或手工步骤；② 客户端预算类指标为验收项，端到端目标为监控项；③ 涉及外部服务的失败路径必须有可操作提示，不允许静默失败或伪造结果。
4. **UI 视觉一致性走查（NFR-16）**：统一令牌见《技术方案》第 15 章。走查页面为知识库、面试辅助（含迷你模式与快捷条）、会话历史、设置、首次启动向导；检查项为圆角档位归位、无「内层圆角大于外层」、卡片阴影与描边一致、按钮/输入框悬停与键盘聚焦反馈可见、卡片内边距节奏一致。该走查不新增自动化用例，以 `npm run verify`（前端构建 + 279 项单测）作为回归基线。

> 基线：Rust 约 377 项、前端约 279 项（随迭代增长，以 `README.md` 与 CI 结果为准）。

## 13. 风险与开放问题

| 编号 | 风险/问题 | 影响 | 应对 |
|---|---|---|---|
| RK-01 | 本地 ASR native 推理未接入 | 真实麦克风转写不可用 | 接入点明确；当前显式报错而非伪造文本；验收走一键演示 |
| RK-02 | 本地嵌入仍为 Mock，且 bge-m3 约 2.27GB | 语义召回质量有限、首次下载成本高 | 不可用时降级关键词检索并提示；按评测集（Recall@5 / MRR@10）验收后再决定是否下调模型 |
| RK-03 | BGE / VAD 模型 SHA256 未填 | 完整性校验形同虚设 | 接入真实推理前补齐并打开强制校验 |
| RK-04 | 模型下载源单一（魔搭社区） | 源不可达则模型不可用 | 内联提示 + 重试；功能降级为关键词检索 |
| RK-05 | macOS 系统音频需屏幕录制授权 | 首次体验门槛 | 向导引导授权，未授权明确告知受限范围 |
| RK-06 | 云端 ASR 多厂商协议不兼容 | P1 排期风险 | 延至 P1，`AsrProvider` 抽象保留，上层链路零改动 |
| RK-07 | 端到端延迟依赖外部服务商 | 指标归属争议 | 拆分为客户端预算（验收）+ 端到端目标（监控） |
| RK-08 | 无边框第二窗口的失败模式不可恢复 | 体验死锁（已发生） | 已改为应用内就地切换（IA-13），并禁止引入同类形态 |
| RK-09 | 隐身/防录屏的合规灰色地带 | 产品定位风险 | 文案谨慎，明确用途边界 |
| OP-01（开放） | 是否接受 2.27GB 嵌入模型作为默认？是否提供小模型选项？ | 影响安装包与首启体验 | 待产品决策 |
| OP-02（开放） | 本地 ASR 与本地嵌入同时加载时的内存上限？ | 影响低端机可用性 | 待实测确定 |
