# 轻松面试桌面客户端 — 技术方案

> 版本：v0.14（15.5 IA-07 召回展示位收敛：问题识别面板移除重复的「知识库参考」区块，召回触发迁移到 AI 回答面板） · 状态：草案 · 产品名：轻松面试（Easy Interview） · 目标平台：Windows 10/11、macOS 13+
> 命名与标识：exe / Cargo crate `easy-interview`；bundle identifier 与钥匙链服务名 `com.easyinterview.app`；数据库 `easy-interview.db`；数据目录由 identifier 决定（Windows `%APPDATA%\com.easyinterview.app\`，macOS `~/Library/Application Support/com.easyinterview.app/`）；本地持久化键 `ei.locale`、`ei.theme`
> 配套文档：`ai-doc/需求分析.md`（v1.0，场景/用例、需求条目与验收标准、追溯矩阵）。本文第 2 章为需求总表，详细展开见需求分析文档。

## 1. 项目概述

### 1.1 定位
轻松面试桌面客户端，为求职者在远程面试场景中提供两大核心能力：

1. **知识库**：Markdown 笔记的导入、编辑、维护、群组管理，以及全文/语义检索。
2. **面试辅助**：实时捕获面试官语音 → 流式转文字 → 检索知识库 → 结合 AI 生成回答。

### 1.2 设计原则
| 原则 | 说明 |
|---|---|
| 本地优先 | 笔记、检索、会话数据默认本地存储，知识库离线可用 |
| 低资源占用 | 安装包 < 20MB（不含按需下载的模型，也不含随包分发的 ONNX Runtime 动态库）；空闲内存 < 100MB（不含本地 ASR 加载时的模型内存） |
| 低延迟 | 客户端预算：检索 < 200ms、IPC 事件 < 50ms、首帧渲染 < 100ms；端到端目标（依赖外部服务）：ASR < 1s、AI 首 token < 2s |
| 隐私可控 | 本地 ASR 为默认通路（音频不出本机）；云端 ASR 需用户在隐私设置显式同意上传音频（P1 已接入阿里云百炼，其余服务商待接入）；API Key 不明文落盘 |
| 双平台一致 | Windows 与 macOS 提供一致体验 |

### 2.4 非功能需求
- **性能（两类指标拆分验收）**：
  - 客户端预算（本地可控、可测试）：安装包 < 20MB（不含模型）；空闲内存 < 100MB；检索 < 200ms；IPC 事件延迟 < 50ms；界面首帧渲染 < 100ms。
  - 端到端目标（依赖外部网络与服务商，仅做监控打点不作为客户端验收）：ASR 端到端 < 1s；AI 首 token < 2s。
- **隐私**：默认本地存储；云端 ASR 由首次启动向导显式选择开启，可随时切换为本地；API Key 不明文落盘。
- **安全**：HTTPS、系统密钥链、本地敏感字段加密。
- **可用性**：知识库离线可用；AI 需联网；云端 ASR 需联网，本地 ASR 需首次下载模型。
- **可维护性**：模块化、Provider 抽象、双平台 CI。
- **测试策略**：Rust 核心模块单元测试（分块/jieba 分词/融合排序可纯本地验证）；音频链路用 PCM 文件回放做集成测试，不依赖真实设备。

## 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | **Tauri 2.x (Rust)** | 系统 WebView + Rust 原生能力，轻量化 |
| 前端 | **React 18 + TypeScript + Vite 5** | 生态成熟，Markdown 编辑器方案多 |
| UI | **shadcn/ui + Tailwind CSS** | 现代、可定制、轻量 |
| 状态管理 | **Zustand** | 轻量，适合实时事件流驱动 |
| 数据存储 | **SQLite（rusqlite）+ FTS5 + sqlite-vec** | 单一数据文件，内嵌全文/向量检索 |
| 中文分词 | **jieba-rs** | FTS5 写入/查询前预分词（unicode61 对中文无效），纯 Rust 无平台负担 |
| 向量检索 | **sqlite-vec** | SQLite 内嵌向量虚拟表，抽象 `VectorStore` trait 便于未来迁移 |
| 嵌入模型 | **`BAAI/bge-m3`（ONNX，1024 维）+ ONNX Runtime**，`EmbeddingProvider` 抽象 | 本地推理、文本不出本机、离线可用；详见 6.5（含候选对比、推理栈、384→1024 迁移） |
| 音频 I/O | **cpal（麦克风）+ wasapi（Windows 系统音频端点回环，IA-14）**；macOS 系统音频依赖虚拟回环设备 | 跨平台统一抽象（`AudioCapture` trait），平台差异隔离；Windows 无需立体声混音/虚拟声卡 |
| VAD / AEC | **silero-vad (ONNX)** / **webrtc-audio-processing**（P1） | 轻量 VAD；AEC 与说话人双流同期 |
| 本地 ASR | **sherpa-onnx**（中文 paraformer） | P0 唯一 ASR 通路；音频不出本机，按需加载/卸载 |
| 云端 ASR | **阿里云百炼实时语音识别已接入**（DashScope WebSocket，Bearer 鉴权，Base URL 可配置）；讯飞 / 腾讯 / OpenAI 兼容为待接入位 | 云端作为低延迟可选通路；需用户显式同意上传音频 |
| 云端 ASR 传输 | **`tokio-tungstenite`（`native-tls`）+ 单线程 tokio runtime** | 实时识别需双向流式；引擎独占专职线程并以 `tokio::select!` 调度「送帧 / 收结果」，避免同步 WS 依赖 socket 读超时的脆弱实现 |
| 云端 AI | HTTP SSE，OpenAI 兼容 Provider | DeepSeek/Qwen/GLM/硅基流动/OpenAI 统一抽象 |
| 密钥安全 | **keyring crate** | macOS Keychain / Windows Credential Manager |
| 模型分发 | **模型管理器**：按需下载（魔搭社区 ModelScope 直链）、SHA256 校验、断点续传 | 安装包 < 20MB 不含模型 |

### 3.1 为何选择 Tauri 而非 Electron
| 维度 | Tauri 2 | Electron |
|---|---|---|
| 原生能力 | Rust 插件（音频/钥匙链/托盘/快捷键） | Node 桥接，较重 |
| 后端语言 | Rust（性能 + 内存安全） | JS/TS |

结论：基于轻量化与原生能力优势选择 Tauri 2。

**总体策略**：Rust 侧承担所有重活（音频、VAD、ASR、检索、AI、存储、模型管理），前端只负责展示与交互。实时链路（音频 → ASR → 检索 → AI）全部在 Rust 侧完成，通过 Tauri Event 将 partial/final 转写、流式 token 推送到 WebView，避免跨进程多次序列化，保证低延迟。

### 4.2 核心数据流
```
音频设备 → AudioCapture（双流）→ VAD 分段 → ASR Provider（流式）
  → 转写事件推送前端 + 转写落库（P0）
  → 问题识别触发 → 检索服务（jieba+FTS5 + 向量 + 融合排序）
  → AI Provider（SSE 流式）→ token 事件推送前端 → 会话服务落库
```

## 6. 核心模块设计

### 6.1 音频捕获（audio）

- 定义 `AudioCapture` trait，隔离平台差异；两路采集流统一由 `worker::CaptureWorker`
  在**专用线程**内持有（`cpal::Stream` 与 WASAPI 的 COM 对象都不是 `Send`），对外只暴露
  句柄，因此 `CaptureManager.system` 以 trait 对象暴露（两平台实现类型不同）。
- **Windows（IA-14）**：系统音频走 **WASAPI 端点级回环**（`wasapi` crate，在**播放设备**上
  以 `Direction::Capture` 初始化，crate 内部自动附加 `AUDCLNT_STREAMFLAGS_LOOPBACK`）；
  麦克风走 cpal（WASAPI capture）。**不依赖「立体声混音」或任何虚拟声卡。**
- **macOS**：麦克风走 cpal/CoreAudio capture；系统音频仍依赖 **BlackHole / Soundflower**
  等虚拟回环设备（`cpal` 0.15 无 CoreAudio 回环能力，升级评估见 IA-14.7）。
- 麦克风与系统音频作为两条**独立流**，天然实现「我/面试官」通道近似区分；回环流本身即
  扬声器实际播放内容，作为 AEC 参考比麦克风回采更准确。

```rust
pub trait AudioCapture: Send {
    fn start(&mut self, device_id: &str) -> Result<(), String>;
    fn stop(&mut self) -> Result<(), String>;
    fn take_events(&mut self) -> Result<mpsc::Receiver<AudioChunk>, String>; // 16kHz 单声道 20ms 帧流
}
```

#### 6.1.1 Windows 回环采集实现要点（IA-14）

| 要点 | 说明 |
|---|---|
| 打开方式 | `DeviceEnumerator::new()` → 默认播放设备（或按名匹配 `DeviceCollection::get_device_with_name`）→ `get_iaudioclient()` → `initialize_client(&fmt, &Direction::Capture, &StreamMode::EventsShared{..})` |
| 格式 | 请求 f32 / 48kHz / 立体声 + `autoconvert: true`，由音频引擎与设备混音格式互转；随后复用 `normalize_to_16k_mono` + `push_samples` 降混重采样分帧 |
| 事件模型 | 事件驱动（`Handle::wait_for_event`，超时 200ms）。**播放端点空闲时 WASAPI 可能不再触发事件**，故超时按「暂时无数据」处理并继续轮询，而非报错 |
| 样本解码 | `AudioCaptureClient::read_from_device_to_deque` 取原始字节，按小端 f32 解码（`drain_f32_le`，保留不足 4 字节的尾部） |
| 设备语义 | 「系统音频」的来源是**播放设备**：未指定时取系统默认播放设备；设置页与采集面板的设备列表保持一致 |
| 失败处理 | 无可用播放设备时返回可操作错误；**不再降级为默认麦克风**（避免「面试官」通道静默采到「我」的声音） |
| 依赖 | `[target.'cfg(windows)'.dependencies] wasapi = "0.24"`（MIT；依赖 `windows 0.62`），非 Windows 构建不引入 |

### 6.2 VAD / 回声消除
- **VAD（P0，实际实现为能量 VAD）**：`EnergyVad` 以 `rms_level(frame) >= 门限` 逐帧判定，`VadSegmenter` 负责状态机（`min_speech_ms=200` 起段、`min_silence_ms=400` 收段、前后 padding 100ms、单段上限 15s），20ms 帧。
  - **门限语义**：界面「VAD 阈值」是 0~1 的**灵敏度**，经 `threshold_to_rms` 按对数映射为绝对 RMS（`0 → -60dBFS`、`0.5 → -33dBFS`、`1 → -6dBFS`）。**不可**把滑杆值直接当 RMS 用：真实语音/回环 RMS 通常 0.01~0.2，直接比较会让默认 0.5 过滤掉全部语音（2026-09-28 修复的「有电平无转写、无报错」根因）。
  - 抽象 `VoiceActivityDetector` 保留，后续可无缝替换为 silero-vad（ONNX，模型已在 ST-10 清单中）。
- **AEC（P1）**：P0 阶段麦克风流尚无 ASR 消费方（说话人双流在 P1），AEC 无实际收益，故降级与 IA-05 同期交付。实现采用 webrtc-audio-processing；若平台系统 AEC 可用则优先系统 AEC，降低 CPU 占用。

### 6.3 ASR（asr）
- **P0 通路（已决策）**：**只做本地 ASR 通路**（sherpa-onnx 中文 paraformer），音频不出本机。云端多厂商协议适配整体延至 P1。
- **抽象保留**：`AsrProvider` trait 与云端服务商配置（讯飞/阿里/腾讯 + 凭证钥匙链存储）**保留不动**，P1 接入时只需新增各家的协议实现，上层链路（VAD→分段→转写事件→落库→检索→AI）零改动。
- **本地引擎接口**：`LocalAsrEngine` trait（段级识别：`transcribe_segment(&[f32]) -> Option<String>`），P0 提供：
  - `SherpaOnnxEngine`：需要 ST-10 下载的本地模型；模型缺失/损坏时返回**可操作的错误提示**（引导去「设置 → 模型管理」下载或重下），不静默降级；
  - `ReplayEngine`：确定性回放引擎，仅用于单元/集成测试与离线演示。
- **流式体验**：VAD 负责分段，段内按固定间隔（默认 800ms）对当前累积音频重复识别以产出 **partial**，段结束时产出 **final** 并落库（`transcript_segments`），保证崩溃不丢数据。
- 输出 partial / final 事件，携带通道标记说话人。

#### 6.3.1 原生推理接入（IA-15）

| 项 | 决策 |
|---|---|
| 依赖 | `sherpa-rs`（MIT，`sherpa-rs-sys` 绑定 sherpa-onnx C API），**仅 Windows**，且由 cargo 特性 `local-asr-native` 控制（默认关闭） |
| 为何用高层封装 | `ParaformerRecognizer` 内部完成 fbank / LFR / CMVN 特征提取与解码，我们只需喂 16kHz 单声道 f32 PCM（即管线输出格式），免去自研 Kaldi 兼容特征工程的数值风险 |
| 生命周期 | 识别器**懒加载**（首次 `transcribe_segment` 时加载，int8 模型约 200MB 内存），`finish()` 释放；`list_asr_engines` 只做文件存在性检查，不加载模型 |
| 原生库获取 | `sherpa-rs-sys` 的 build.rs 按 target triple 从 k2-fsa/sherpa-onnx Releases 下载预编译包（Windows `x86_64-pc-windows-msvc` shared 归档约 23MB）→ SHA256 校验 → 缓存于系统 cache 目录 → 自动把 DLL 复制到 `target/<profile>/` |
| 构建前置 | 构建机需 **libclang**（bindgen 依赖）。示例：取 PyPI `libclang` 包内的 `libclang.dll`（约 25MB，无需装完整 LLVM）放到 `.libclang/bin/`（已 gitignore），构建时设 `LIBCLANG_PATH` |
| 关闭特性时 | 走 `#[cfg(not(all(windows, feature = "local-asr-native")))]` 分支，返回**明确的构建指引**错误；`cargo test` / 日常 CI 不受 libclang 与原生库下载影响 |
| 打包 | DLL 需与 exe 同目录：构建时由 `sherpa-rs-sys` 的 build.rs 复制到 `target/<profile>/`；**安装包**由 `tauri.local-asr.conf.json`（经 `tauri build --config` 附加）的 `bundle.resources` 携带。**不可**写进 `tauri.windows.conf.json`：该文件对所有 Windows 构建生效，未启用特性时资源不存在会让打包直接失败（实测 `resource path ... doesn't exist`），CI 会挂 |
| macOS | 同一 crate 支持 `*-apple-darwin`，待办见需求分析 TODO-01（需 dylib 打包与 rpath 处理） |
| 已知代价 | 非流式模型：partial 需对累积音频反复整体解码，长段落有 CPU 开销；必要时调大 partial 间隔或限制累积窗口 |

```rust
pub trait AsrProvider: Send {
    fn connect(&mut self, cfg: AsrConfig) -> Result<()>;
    fn feed(&mut self, chunk: AudioChunk) -> Result<()>;        // 流式喂入
    fn events(&self) -> mpsc::Receiver<AsrEvent>;               // partial/final
}
```

#### 6.3.2 云端通路接入（IA-16）

P0 只做本地通路，云端「模式切换 + 凭证表单」保留但被 `CLOUD_ASR_IMPLEMENTED` 常量拦截。P1 把云端从「可配置不可用」推进为「阿里云可用、其余待接入」：

| 项 | 决策 |
|---|---|
| 通道抽象 | 新增 `AsrChannel`（`push_frame` / `flush` → `Vec<TranscriptEvent>`）：`impl AsrChannel for AsrPipeline` 为纯委托（本地行为不变），`CloudChannel` 包装云端引擎；`DualChannelSession` 与单/双通道采集泵统一持有 `Box<dyn AsrChannel>`，AEC 参考缓冲（`ReferenceBuffer`）逻辑原样复用，不再写第二条并行泵 |
| 云端引擎接口 | `CloudAsrEngine`（`feed` 送帧 / `drain` 非阻塞取结果 / `finish` 结束任务并冲刷），工厂 `connect_cloud_engine(EngineSpec)` 按服务商分派；未接入服务商返回**可操作错误** |
| 传输选型 | `tokio-tungstenite`（`native-tls`）+ 单线程 tokio runtime：引擎独占专职线程，`tokio::select!` 在「待发送音频」与「WS 读流」之间公平调度，无需依赖 socket 读超时的脆弱实现；`native-tls` 在 Windows/macOS 复用系统信任库（企业代理自签 CA 场景更稳），不引入 OpenSSL |
| 首期服务商 | 阿里云百炼 DashScope 实时语音识别：`wss://dashscope.aliyuncs.com/api-ws/v1/inference`（可被 Base URL 覆盖），建连头 `Authorization: Bearer <api_key>`；JSON 文本帧下发 `run-task` / `finish-task`，二进制帧送 PCM16 LE 音频（16kHz 单声道，由管线 f32 转换） |
| 模型 | 默认 `qwen-audio-3.1-asr-flash-streaming`（官方推荐的实时模型；Gummy 系已标注「即将下线」）。实测可用的实时模型：`qwen-audio-3.1-asr-flash-streaming`、`fun-asr-realtime`、`paraformer-realtime-v2`；**非实时（HTTP 文件转写）模型不可用**（如 `qwen-audio-3.1-asr-flash` 会被服务端以 `ModelNotFound` 拒绝），`qwen3-asr-flash-realtime` 走另一套会话事件协议/端点，当前实现未支持 |
| 结果映射 | 服务端句级结果（`result-generated`）：句未结束 → `TranscriptEvent::Partial`（不落库）；句结束 → `Final`（落库）。**云端模式不启用本地 VAD 分段**，避免双重切分与重复落库；音频按实时率持续送帧，不做静音裁剪（避免服务端「长时间无音频」超时） |
| Base URL | `AsrConfig.cloud_base_urls: BTreeMap<CloudAsrProvider, String>`（`#[serde(default)]` 兼容旧配置），**每个服务商各存一份**；空值表示使用该服务商官方默认。校验允许 `ws(s)://` / `http(s)://`，http(s) 在建连前自动改写为 ws(s)，兼容反向代理写法 |
| 启动时机 | 建连与 `task-started` 握手在 `start_asr_session` / `start_dual_asr_session` 命令内**同步完成**（沿用 `test_ai_connection`、`capture.start()` 的阻塞 I/O 惯例）：凭证 / 地址 / 模型错误在点击「开始转写」时立即以可操作文案返回；成功后把引擎（线程句柄 + 通道）移交采集泵 |
| 错误与资源 | 凭证缺失 / 鉴权失败 / 地址非法 / 中途断连 → 一次 `TranscriptEvent::Error`（沿用相同错误去重策略），不伪造文本；停止会话必定 join 引擎线程，`finish()` 带超时（约 3s），不泄漏连接 |
| 上传同意 | 云端模式要求隐私设置 `upload_audio = true`（显式同意上传音频）；未同意时开始转写给出可操作提示（对齐 `PrivacyConfig::validate`） |
| 连接测试 | `test_cloud_asr_connection`：按当前服务商与 Base URL 建连并等到 `task-started` 即视为通过，返回耗时；失败不写入任何配置 |
| 测试 | `asr/cloud/mock.rs` 在 `127.0.0.1` 起本地 WS 服务端，驱动「run-task → task-started → 音频 → result-generated → finish-task → task-finished」时序，并注入鉴权失败 / 中途断连路径，断言事件序列 |

> 上层零改动：云端与本地共用「采集泵 → `AsrChannel` → `TranscriptEvent` → 事件广播 / final 落库 / 问题识别 → 召回 → AI 回答」链路，仅通道实现不同。

### 6.4 AI（ai）
- 统一 OpenAI 兼容 Provider：DeepSeek / Qwen / GLM / 硅基流动（SiliconFlow）/ OpenAI 共用同一协议，可插拔适配。
- 平台枚举 `AiPlatform`（`src-tauri/src/config/mod.rs`）为唯一事实来源：新增平台只需加变体并在 `preset()` 补 Base URL 与默认模型，`all_presets()` 自动供设置页渲染。
- 平台标识变更留兼容：`Openai` 变体带 `#[serde(alias = "chatgpt")]`，`AiPlatform::parse` 亦接受 `chatgpt`，历史配置迁移无需洗数据。

- SSE 流式输出，连接复用/预热，目标首 token < 2s，含超时与重试策略。

#### 6.4.1 思考 / 非思考模式（ST-12）

**背景（2026-09-28）**：此前请求体只含 `model / messages / temperature / stream`，思考行为完全由模型默认值决定。`qwen-plus` 等非思考模型首字快；而百炼上的 `qwen3.5`~`qwen3.8` 系列（含 `qwen3.8-flash`、`qwen3.7-flash-2026-07-15`）`enable_thinking` **默认为 true**，先产出整段思维链再输出正文；同时思考增量字段 `reasoning_content` 未被解析，前端在整个思考阶段没有任何可见输出，表现为「长时间无响应」。面试实时作答需要可预测的低首字延迟，因此把模式显式化。

**分平台下发方式（`src-tauri/src/providers/thinking.rs`）**

| 平台 | 请求参数 | 思考 | 非思考 |
|---|---|---|---|
| 通义千问 Qwen（百炼兼容模式） | 顶层 `enable_thinking` | `true` | `false` |
| 硅基流动 SiliconFlow | 顶层 `enable_thinking` | `true` | `false` |
| 智谱 GLM（`/api/paas/v4`） | `thinking.type` | `"enabled"` | `"disabled"` |
| DeepSeek | 无参数（模型名区分：`deepseek-chat` / `deepseek-reasoner`） | 不下发 | 不下发 |
| OpenAI | 无布尔开关（`reasoning_effort` 非等价语义） | 不下发 | 不下发 |

- 平台能力经 `PlatformPreset::thinking_param` 单向下发到设置页（`Some("enable_thinking")` / `Some("thinking")` / `None`），前端不重复维护平台判断，`None` 时就地提示「需通过模型名区分」。
- 仅下发 `enable_thinking`，**不**下发 `thinking_budget`：流式场景下 `enable_thinking: false` 已足以关闭推理，额外参数只会增加 400 风险。
- 参数 `apply()` 返回实际写入的顶层键，供回退时精确移除。

**失败回退（关键容错）**：并非所有模型都接受该参数（如 `qwen-plus` + `enable_thinking`）。`stream_chat` 首次请求返回 4xx 且错误体命中「thinking + unsupported/unknown/invalid/不支持」等关键词时，判定为该参数不被支持 → 移除参数**重试一次**，并 `tracing::warn!` 记录；重试仍失败才向上报错。这样开关只影响参数下发，不会让回答功能本身变脆。

**默认值与兼容**：`ThinkingMode` 默认 `NonThinking`（`#[serde(default)]`），旧 `ai.config` 无该字段时自动按非思考处理，无需洗数据。切换平台只覆盖 Base URL 与默认模型，不重置用户已选的模式。

### 6.5 Embedding（embedding）

#### 6.5.1 选型结论

**默认本地嵌入模型定为 `BAAI/bge-m3`（ONNX，1024 维）**，搭配 ONNX Runtime 本地推理。

> **更新说明（2026-09-27）**：嵌入模型已由 `bge-small-zh-v1.5`（512 维）改为 `BAAI/bge-m3`（1024 维），下载源统一固定为魔搭社区（ModelScope）。本次仅落地「下载源切换 + 模型清单 + 维度迁移（384→1024）」，本地 ONNX 推理仍待接入（当前用 Mock）；下文 6.5.2 候选对比与 6.5.5 性能预算为历史论证，仅供参考。

- `EmbeddingProvider` trait 保持三种实现：本地 ONNX（默认）、云端 API（P1，需隐私开关显式同意）、Mock（离线开发/演示用）；
- 默认本地推理：笔记正文与问题文本均不出本机，知识库完全离线可用，无网络往返；
- 性能目标：单次查询嵌入 < 30ms，确保与 FTS5 召回合计仍满足「检索 < 200ms」客户端预算（预算核算见 6.5.5）。

#### 6.5.2 候选对比与选择理由

| 候选 | 维度 | 体积（ONNX） | 中文检索能力 | 需 query 指令 | 结论 |
|---|---|---|---|---|---|
| **BAAI/bge-small-zh-v1.5（int8）** | 512 | 约 23MB（量化）/ fp32 约 130MB | C-MTEB 平均 57.82、检索 61.77，同尺寸中文第一梯队 | 建议（v1.5 已弱化，可关） | **选定** |
| BAAI/bge-small-zh-v1.5（fp32） | 512 | 约 130MB | 同上（略优于 int8） | 同上 | 备选：追求最后 1–2% 精度且不计体积时 |
| moka-ai/m3e-small | 512 | fp32 约 100MB / int8 约 30MB | 中文对称检索良好 | 否 | 备选：不愿引入 query 指令时采用（引入前须复核许可证） |
| paraphrase-multilingual-MiniLM-L12-v2（或其微调版 text2vec-base-multilingual） | 384 | fp32 约 470MB / int8 约 120MB | 中文明显弱于专项中文模型 | 否 | 唯一优势是维度与现 schema 一致；体积大、效果弱，**不推荐** |
| text2vec-base-chinese / bce-embedding-base_v1 / gte-Qwen 系列 | 768+ | 0.4–2GB | 更强 | 视模型而定 | 超出「小模型 + 低内存」预算，不做 |
| 云端 Embedding（OpenAI text-embedding-3-small、各家大模型 Embedding API） | 1536+ | 本机 0 | 取决于厂商 | 否 | 违背本地优先与隐私默认；仅在用户显式同意上传文本时可选（P1） |

选择 bge-small-zh-v1.5 的理由：

1. **质量/体积比最佳**：同为可放进「按需下载清单」的小模型，中文语义召回显著优于 384 维多语言系列；
2. **体积与内存可控**：int8 约 23MB，常驻内存增量约 60–100MB，远低于 768 维 / base 级模型；
3. **序列长度与分块策略天然对齐**：最长 512 token，与笔记分块默认 512 token（6.6）一致，无需额外二次截断；
4. **可直接复用现有模型管理器**：Apache-2.0 许可，`model_quantized.onnx` + `tokenizer.json` 走现有「下载 → SHA256 校验 → 断点续传」通路；
5. **生态成熟**：量化/导出脚本与第三方 ONNX 产物齐全，便于自建镜像源（6.5.6）。

#### 6.5.3 Rust 侧推理栈

- 运行时：`ort`（ONNX Runtime 1.19+），InferenceSession 单例复用，线程数限制为 2，避免与音频采集 / 本地 ASR 争抢 CPU；
- 分词：`tokenizers` 加载随模型下载的 `tokenizer.json`（BERT 中文 WordPiece，vocab 21128），不引入 Python/Torch 运行时；
- 交付：`ort` 使用 `load-dynamic`，Windows 随包 `onnxruntime.dll`、macOS 随包 `libonnxruntime.dylib`（约 15–20MB/平台）。**安装包口径据此更新**：主程序 < 20MB（不含 ORT 动态库与模型）；ORT 动态库计入安装包，模型仍按需下载；
- 生命周期：首次检索/索引时按需加载 Session，空闲 10 分钟卸载，落实「空闲不驻留」内存约定。

#### 6.5.4 输入输出约定

- 输入：单条最长 512 token（超出截断），批大小默认 8（`reindex_note` 按批调用 `embed`）；
- 池化与归一化：**导出 ONNX 时把池化（取 `[CLS]` 表示）与 L2 归一化固化进计算图**，Rust 侧只负责推理与拷贝——避免上层重复实现，也避免脚本与 Rust 实现不一致造成向量漂移；
- 向量已归一化，余弦相似度与内积等价，与 sqlite-vec KNN 的距离排序单调一致；
- Query 指令：bge 官方建议在检索侧 query 前拼接 `为这个句子生成表示以用于检索相关文章：`（文档侧不加）。默认开启，并在 ST-06 提供开关以便 A/B；**换模型时必须同步更换或关闭该指令**，否则召回质量反而下降。

#### 6.5.5 性能预算（4 核笔记本 CPU）

| 场景 | 估算 | 说明 |
|---|---|---|
| 查询文本嵌入 | 5–20ms/条 | 短 query（<64 token）取下限 |
| 单篇笔记建索引（约 10 块） | < 300ms | 后台任务 + 进度事件 |
| 全量重建 1 万块 | 1–3 min | 后台分批，可中断续做 |
| 向量 KNN（sqlite-vec 暴力扫描，1 万条 ×512 维） | < 10ms | 规模到 50 万块再考虑替换 `VectorStore` 实现 |
| 磁盘占用 | 2KB/块（512×f32），1 万块约 20MB | 可接受 |

检索预算核算：查询嵌入（≤20ms）+ FTS5 召回 + KNN（≤10ms）+ 融合排序，距 200ms 预算仍有充分余量。

- SHA256 必填：当前 `catalog()` 中 sha256 为空（等价于跳过校验），接入真实推理前必须补齐并打开强制校验。

#### 6.5.7 维度 384 → 1024 的迁移（已落地）

现状：`migrations/001_init.sql` 声明 `vec_chunks.embedding float[384]`，`storage::EMBEDDING_DIM = 384`。选定模型为 1024 维，需一次性迁移（已实现）：

1. 新增 `migrations/002_embedding_1024.sql`：删除旧 `vec_chunks`，重建为 `float[1024]`；
2. `storage::EMBEDDING_DIM` 改为 1024，`SCHEMA_VERSION` 升到 2；迁移时通过 `Db::did_rebuild_embedding()` 标记本次打开是否发生维度迁移；
3. 打开旧库且发生维度迁移时：清空 `vec_chunks`，由启动流程触发全量向量重索引（`retrieval::index::reindex_all`），失败仅告警不阻断启动；FTS5 全文检索不受影响；
4. 单测与集成测试中硬编码的维度统一改用 `EMBEDDING_DIM` 常量。

#### 6.5.8 验收方式

- 构造评测集：20–30 条真实面试问题 + 人工标注的相关笔记；
- 指标：Recall@5 / MRR@10，对比三路——纯 BM25、BM25 + bge-small-zh(int8)、BM25 + MiniLM-384；
- 验收线：混合检索 Recall@5 不低于纯 BM25（不退化），且 bge 路不低于 MiniLM 路；若差距不明显需在文档记录结论，并据此评估是否下调/更换嵌入模型。

### 6.9 迷你模式（Mini View）
- 前端页面右上角提供「缩小」按钮：点击后**整个界面就地切换**为迷你页，体验类似桌面便签；仅展示当前识别到的面试官问题 + AI 流式回复（含引用来源标签）。
- **实现方式（就地模式）**：不创建第二 WebView，改为「应用内视图切换 + 主窗口几何调整」：
  - 前端：`appStore.miniMode` 控制 `App.tsx` 早退渲染 `MiniView`；`MiniView` 头部提供「恢复」「退出应用」两个入口。
  - 后端：`enter_mini_mode` / `exit_mini_mode` 命令负责主窗口几何——进入时记录快照（尺寸/位置/是否最大化/进入前置顶状态）并切换为 420×340、最小 320×200、置顶；退出时按快照还原尺寸/位置/最大化，置顶还原为 `interface_config.always_on_top`。
  - 统一入口：标题栏按钮、应用内/全局热键 `Ctrl+Shift+M`、托盘「迷你模式」菜单均走同一 `toggle_mini` 语义（托盘经 `shortcut://action` 广播触发）。
- **为何弃用独立第二窗口**：第二窗口为 `decorations(false)`，其全部交互（拖动区、关闭按钮）依赖 WebView 内部渲染；一旦第二个 WebView 未成功渲染即退化为「空白方框 + 无法拖动 + 无法关闭」的不可恢复死锁。就地模式把可用性与主界面渲染强绑定（主界面已被证明可靠），失败模式被结构性消除。
- **内存取舍**：复用主窗口 WebView，**不再产生第二 WebView 的 +40–60MB 激活态开销**；迷你模式自身不新增常驻内存（仅一次窗口属性读写与快照存取）。
- 配合窗口置顶与全局快捷键使用；迷你模式状态不持久化（会话内有效）。

### 6.13 问题识别（IA-06）

- **触发链路**：采集泵（单路 `start_asr_session` / 双路 `spawn_dual_pump`）→ 仅取**面试官通道的 final**（`Speaker::Interviewer`）→ `feed_questions` → `QuestionDetector::push` → 命中即 `handle_detected_question`（写 `qa_pairs` + 广播 `interview://question`）；前端 `useQuestionEvents` → `interviewStore.applyQuestionPush` → `QuestionPanel` 展示、`AnswerPanel` 自动生成回答。「我」通道的转写不参与识别（避免把自己的话当问题）。
- **判定规则**（规则式：零模型、零额外延迟、可解释）：强信号 = 句末问号（+0.6）/ 疑问词（+0.55）/ 祈使式提问（+0.55）；弱信号 = 句中第二人称疑问（+0.45）/ 句尾语气词「吗/呢」（+0.4）。默认阈值 0.5、最短 4 字（`QuestionConfig` 可调）；整段为纯应答/语气词（「嗯」「好的」）直接排除。
- **判定单位是「句」而不是「整段」（2026-09-28 修复）**：一条转写（云端按 `sentence_end` 返回的 final 尤其如此）常包含多句话，按整段判定会让句中信号被后面的文字稀释：
  - 反例（真实踩坑）：`呃第一个问题，lvm了解过吗？假如你有块新的磁盘，你要用lvm的方式挂载到指定的目录，你说一下这个过程中用到的命令。`
  - 整段判定：句尾是句号 → 问号信号不成立、无疑问词命中 → 得分 0 → 问题被静默丢弃。现象是「转写面板里明明有这句、问题识别却一直为空、AI 回答也不生成，直到下一句问题才恢复」。
  - 现方案：`split_sentences` 按句末标点（`。！？!?；;` 与换行）切句 → `analyze_sentence` 逐句打分 → **取最高分作为整段结论**（任一句命中即整段视为问题）；上报文本仍是整段原文（保留问句与其后的补充说明，利于召回与回答质量）。
- **跨段聚合与去重**：`merge_window_ms`（默认 3s）内的连续转写合并为一个候选（面试官中途停顿分词）；超过 `stale_ms`（10s）仍未命中疑问特征的候选丢弃；`last_emitted` + 前缀相似判定避免同一问题续段重复上报。
- **可诊断性**：命中时写 `info` 日志（字数 / 得分 / 自动或手动），候选超时丢弃写 `debug` 日志；**只记长度与得分、不落正文**（转写正文属用户内容）。排查「为何没识别到」直接看 `<数据目录>/logs/app.log.<日期>`。
- **前端会话清理**：开始转写（单路/双路）时除清空转写与问题外，同步归零 `answerText/answerStatus/answerError/answerQaId/answerModel`，避免重启转写后仍残留上一场的问题与回答。

### 6.14 主题系统（ST-13）

- **问题**：`InterfaceConfig.theme` 前后端都能存能读，但**没有任何代码把它应用到界面**：前端全仓库无 `documentElement` / `classList` 操作，`index.html` 写死 `<html class="dark">` 与 `<meta name="color-scheme" content="dark">`，`tailwind.config.js` 的颜色是硬编码 hex，`src/index.css` 的 `body` / 滚动条 / `.glass` / `.markdown-body` / `.cm-editor` 全是深色字面量，约 27 个组件中的描边与悬停态写作深色专属的 `white/[…]` 叠加。故点「浅色」无任何变化，且浅色配色从未设计。

- **方案：语义颜色令牌（CSS 变量）+ 主题运行时两层**，让绝大多数组件零改动：

  1. **令牌层**：`tailwind.config.js` 的颜色全部改为 `hsl(var(--x) / <alpha-value>)`（`ghost` 为 `rgb(var(--ghost) / <alpha-value>)`），在 `src/index.css` 的 `:root`（浅色）与 `.dark`（深色）定义同一批变量。既有 `bg-background-3/60`、`bg-primary/15`、`text-primary-3`、`border-border` 等类名两主题自动成立。
  2. **幽灵叠加令牌**：把「深色下叠白、浅色下叠黑」的语义收敛为 `ghost`（深色 `255 255 255`、浅色 `15 20 32`），组件侧把 `border-white/[0.06]` → `border-ghost/[0.06]`、`hover:bg-white/[0.06]` → `hover:bg-ghost/[0.06]` 机械替换即可双主题正确。
  3. **运行时层**：`src/lib/theme.ts`（纯函数，可单测）+ `src/hooks/useThemeSync.ts`（副作用），以 `settingsStore` 为唯一事实来源，统一负责解析、应用与首屏缓存。

```ts
export type ResolvedTheme = "dark" | "light";
export type ThemeSetting = "dark" | "light" | "system";

export function resolveTheme(setting: ThemeSetting, systemTheme: ResolvedTheme): ResolvedTheme;
export function applyTheme(theme: ResolvedTheme): void;   // 切 html.dark + color-scheme meta + 写 ei.theme 缓存
export function loadThemeCache(): ResolvedTheme | null;   // index.html 内联脚本与运行时共用
```

| 层 | 文件 | 职责 |
|---|---|---|
| 令牌 | `tailwind.config.js`、`src/index.css` | `:root` = 浅色取值、`.dark` = 深色取值；`--ghost` / `--glass-*` / `--shadow-*` / 滚动条色 |
| 纯逻辑 | `src/lib/theme.ts` | 设置值 → 实际主题解析、应用到 DOM、首屏缓存读写 |
| 副作用 | `src/hooks/useThemeSync.ts` | 订阅 `previewTheme` + `interfaceConfig.theme`，解析后 `applyTheme`；`system` 模式时注册 Tauri `onThemeChanged`（回落 `matchMedia`），退出时注销 |
| 状态 | `src/stores/settingsStore.ts` | `previewTheme: InterfaceTheme \| null` + `setPreviewTheme` / `clearPreviewTheme`；解析优先级 `previewTheme ?? interfaceConfig.theme ?? "dark"` |
| 入口 | `src/App.tsx` | 顶层（迷你模式与向导早退**之前**）调用 `useThemeSync()`，Hooks 不可条件调用 |
| 首屏 | `index.html` | 内联极小脚本读 `localStorage["ei.theme"]` 先设 class 与 `color-scheme`，消除闪烁（FOUC） |

- **关键决策**：
  - 用 CSS 变量而非逐组件 `dark:` 变体：项目已有约 27 个文件、60+ 处颜色类名，逐一变体会造成大面积改动与重复；令牌方案把改动集中在 2 个配置文件 + 一次机械替换。
  - 即时预览用 `previewTheme` 进 store 而非直接操作 DOM：DOM 直改会在「保存 / 切页 / 回滚」时状态失同步；预览态进 store 后，回滚只需清空预览态。
  - 「跟随系统」走 Tauri `getCurrentWindow().theme()` / `onThemeChanged()`（反映系统真实主题、可与原生窗口背景一致），非 Tauri 环境回落 `matchMedia("(prefers-color-scheme: dark)")`。
  - 浅色下 `primary-3`（前景）由 `#7C9AFF` 加深为 `#2B46C4`，`success/danger/warning` 同步加深，保证白底可读；深色取值一律不变以作为零回归基线。
  - `shadow-card` 等四项改为引用 `var(--shadow-*)`，浅色下阴影更轻。

- **后端**：`Theme` 枚举新增 `System` 变体（`#[serde(rename_all = "lowercase")]` → `"system"`），`Default` 仍为 `Dark`，旧数据（`"dark"` / `"light"`）保持兼容，无表结构变更。

- **不与既有约定冲突**：ST-11 反馈语义（`error` / `notice` / `testResult` / `modelErrors` 与 `fail()`）只增不改；主题选择本身不触发保存反馈，仅「保存配置」触发；圆角六档、间距、`.focus-ring`、`shadow-card` 使用位置与面试页两列布局约定（见 15.5）一律不动。

### 6.15 命令执行模型与主线程阻塞治理（2026-09-29）

- **问题现象**：知识库 / 面试辅助 / 会话历史 / 设置四个主页互切时，点击侧边导航后要等一段时间界面才真正切过去；**未开始转写、未开启一键演示的空闲状态下同样复现**（故与后台 ASR / 演示线程无关）。

- **根因（已核验到依赖源码，非文档推测）**：
  1. **所有命令都在主线程同步执行**。`src-tauri/src/commands.rs` 中 `#[tauri::command]` 共 **97 处**、`#[tauri::command(async)]` **0 处**（`lib.rs` 的 `app_info` 同样未标注）。`tauri-macros-2.6.3/src/command/wrapper.rs` 中：函数非 async 且属性未带 `async` → `ExecutionContext::Blocking` → `body_blocking`，命令体在 IPC 处理线程（Tauri 主线程）**同步执行**；而 `body_async` 配合 `tauri-2.11.6/src/ipc/mod.rs` 的 `respond_async_serialized` 会把 `#[tauri::command(async)]` 的同步函数投到 `async_runtime::spawn`，即工作线程执行。
     → 切页瞬间各页并发触发一批命令（设置页 7 个 loader + 钥匙链、知识库 4 个、面试辅助 5 个、会话历史 1+1），其中 `audio::list_devices()`（cpal / WASAPI 设备枚举）、`get_api_key_status`（系统钥匙链读取）、`list_models`（模型目录与文件元数据扫描）、`list_notes` / `get_session_detail`（SQLite 查询）均为阻塞操作，串行占满主线程，点击、绘制与窗口消息排队 → 体感「点击后一段时间才跳转」。
  2. **前端切页即整页卸载 + 全量重取**。`src/App.tsx` 用条件渲染切页且四页皆为静态导入（无 `React.lazy` / `Suspense` / 过渡），切换时同步 commit 整棵新子树；各页 `useEffect` 无条件重拉数据；`MarkdownView` 的 `ReactMarkdown + remarkGfm + rehypeHighlight` 每次渲染都全量重新解析与语法高亮，无 memo。
  3. **放大项**：`.glass` 的 `backdrop-filter: blur(16/20px)` 面板数量多，切页需重新光栅合成；`React.StrictMode` 在开发模式下 effect 双跑使上述 IPC 请求翻倍（因此验收须以 release 包为准）。
  4. 全局单连接 `Arc<Mutex<Connection>>` 使命令天然串行，进一步拉长主线程占用时长。

- **方案（保守口径：不改前后端数据契约、不改页面 UI 结构）**：
  1. **命令异步化（主修）**：凡触达 `state.lock()` / 文件系统 / 设备枚举 / 钥匙链 / 网络 / 线程启动的命令，统一加属性 `#[tauri::command(async)]`（**函数体不变**），命令体改由 tokio 工作线程执行。
     编译期约束（来自 `tauri-macros` 的 `async_command_check`）：入参含生命周期泛型（如 `State<'_, AppState>`）且返回值**不是 `Result`** 的异步命令会编译失败，命中处需包一层 `Result` —— 仅 `get_storage_paths`、`list_asr_engines` 两处；成功路径的 JS 侧取值不变（`Ok` 即原值，`Err` 走 reject），不构成数据契约变更。
  2. **豁免白名单（保持同步，共 5 个）**：`save_interface_config`、`set_stealth_window`、`apply_global_hotkeys`、`enter_mini_mode`、`exit_mini_mode` —— 命中窗口几何 / 置顶 / 防录屏与全局快捷键注册等主线程强相关操作，且均不在切页热路径上。
     另：`lib.rs` 的 `app_info` 同样保持同步（纯函数、无阻塞、无生命周期入参，且被 `lib.rs` 单测直接同步调用）；`get_autostart` / `set_autostart` 只做注册表读写、不触碰窗口，最终归入异步一档（与初版方案的豁免设想不同）。
  3. **重阻塞命令落到阻塞线程池**：`list_notes` / `list_trash_notes` / `get_session_detail` / `list_models` / `get_api_key_status` / `list_audio_devices` / `list_loopback_devices` 改为 `async fn` + `tauri::async_runtime::spawn_blocking`，避免占用 tokio worker（默认 worker 数 = CPU 核数）而挤压 SSE 流式回答等异步任务。闭包需先 clone 出 `Arc` / `PathBuf`（`State<'_, _>` 不可移入 `'static` 闭包），闭包内再 `lock()`。
  4. **设备枚举 TTL 缓存**：`src-tauri/src/audio/devices.rs` 把 cpal 枚举体改名为私有 `enumerate_devices()`，`list_devices()` 改为走 `list_devices_cached(false)`（`static Mutex<Option<(Instant, Vec<DeviceInfo>)>>`，TTL 1500ms）。缓存落在**根节点**，故 `list_by_kind` / `render_devices` / `system_source_devices` / `loopback_candidates` 等全部上游调用共享同一份结果，签名与既有单测零改动；`list_devices_cached(true)` 提供强制刷新，命令 `list_audio_devices` 增可选参数 `force: Option<bool>` 供「刷新设备列表」旁路（不传即旧行为）。
  5. **前端低风险渲染优化**：`MarkdownView` 按 `content` memo 化并用 `memo` 对外隔离、`MarkdownEditor` 预览用 `useDeferredValue`、`NoteList` / `GroupTree` 加 `React.memo`；`App.tsx` 中导航高亮仍读 `currentPage`（紧急更新、点击立即反馈），**页面内容改读 `useDeferredValue(currentPage)`**，让整页卸载 / 重挂载作为可中断的低优先级渲染进行（未用 `startTransition` 包 `setCurrentPage`：那会把导航高亮一起降级）。新增 `src/lib/perf.ts`：仅开发期打点「点击 → 目标页首帧」并 `console.debug`，生产构建为空操作。
  6. **防回退**：新增静态测试断言 `commands.rs` / `lib.rs` 中每个 `#[tauri::command]` 均为 `(async)` 或位于显式白名单内。

- **实施结果（2026-09-29）**：97 个命令中 92 个标注 `#[tauri::command(async)]`（其中 7 个重阻塞命令改 `async fn` + `spawn_blocking`），5 个列入白名单保持同步；`cargo test --lib` **445 passed / 3 ignored**（含 2 项命令属性静态断言、1 项设备缓存一致性测试），`npm run verify` 前端 **36 文件 / 344 项**全绿。四页互切的 release 包目视验收为人工步骤。

- **正确性边界**：改造只移动命令体的执行线程，不改查询语句、返回结构、错误与日志语义；`Arc<Mutex<Connection>>` 的互斥语义保持不变（等价于把串行点从主线程搬到工作线程）。音频采集的 COM 初始化由 `CaptureWorker` 专用线程自行完成（`audio/loopback.rs` 的 `initialize_mta()`），故启动类命令移出主线程不影响 WASAPI 端点级回环。

- **验收**：`cargo test`（含命令属性静态断言）+ `npm run verify`；release 包实测四页互切、音频试听、开始/停止转写、钥匙链读写、模型下载与「刷新设备列表」回归；可选 `RUST_LOG=debug` 观察 IPC 日志中 handler 的 `kind` 由 `sync` 变为 `async` / `sync_threadpool`。

## 7. 数据模型

### 7.1 核心表结构
| 表 | 说明 | 关键字段 |
|---|---|---|
| notes | 笔记 | id、title、content、group_id、created_at、updated_at、is_deleted |

| chunks | 笔记分块 | id、note_id、content、position |
| fts_index | FTS5 虚拟表 | title、content、tags（jieba 预分词后存储） |

| sessions | 面试会话 | id、title、started_at、ended_at |

### 7.2 检索索引
- **FTS5 虚拟表**：notes(title, content, tags) 经 jieba-rs 分词后建立全文索引。
- **向量虚拟表**：sqlite-vec 存储 chunk 的 embedding，余弦相似度检索；抽象 `VectorStore` trait。
- **向量维度**：嵌入模型定为 1024 维（bge-m3，见 6.5），故 `EMBEDDING_DIM = 1024`、`vec_chunks.embedding float[1024]`；已按 6.5.7 执行迁移 `002_embedding_1024.sql` 并自动重建语义索引。

## 8. 关键技术决策与权衡

| 决策点 | 方案 | 权衡说明 |
|---|---|---|
| 跨平台音频 | AudioCapture trait + 平台特化 | 隔离 WASAPI / ScreenCaptureKit 差异 |
| 说话人区分 | P1 用「音频通道近似」（麦克风=我，系统音频=面试官） | 零额外成本；真实 diarization 延后 |
| ASR 通路 | **本地（sherpa-onnx）为默认**；云端已接入阿里云百炼实时 WS（IA-16，6.3.2） | 本地通路可离线验证且音频不出本机、隐私默认最优；云端作为低延迟可选通路，需用户显式同意上传音频 |
| 云端 ASR 通道抽象 | 新增 `AsrChannel`（本地段级流水线与云端流式引擎同一出口） | 避免把云端退化为「每段独立建连、整段重发」的假流式；本地与云端共用采集泵与上层链路（事件/落库/问题识别/召回/回答），零改动 |
| ASR 模式切换 | 云端/本地切换 + **各服务商独立 Base URL**（可恢复官方默认）+ 接入状态标注 | Base URL 可指向代理 / 地域专属域名 / 私有化部署；未接入服务商给出可操作错误，不静默失败 |
| 中文检索 | jieba-rs 预分词 | FTS5 默认分词对中文无效，必须预处理 |
| 混合检索 | P0 固定权重融合 → P1 RRF | P0 尽快闭环，P1 精细化 |
| 迷你模式 | **主窗口就地切换 + 窗口几何快照/还原**（Rust 侧控制几何与置顶） | 便签式体验不变；消除第二 WebView 的「空白且无法关闭」死锁风险，且净省激活态 40–60MB 内存，实现更简单、可恢复 |
| 嵌入模型 | **本地 `bge-m3` ONNX（1024 维，约 2.27GB）** | 多语言检索能力强、文本不出本机；代价：体积大、维度 384→1024 需一次 schema 迁移与全量重建索引（6.5.7） |
| 模型分发 | 按需下载 + 校验 + 断点续传 | 安装包 < 20MB 口径不含模型与 ORT 动态库 |
| AEC 时机 | P1 与说话人双流同期 | P0 麦克风流无 ASR 消费方，AEC 无收益 |
| 本地加密 | 字段级 AES-GCM | 规避 SQLCipher 与 sqlite-vec 兼容风险 |
| 密钥安全 | keyring 存系统钥匙链 | 不明文落盘 |

## 9. 性能与优化策略

- **指标拆分**：客户端预算（检索/IPC/渲染，本地可控可验收）与端到端目标（ASR/AI 首 token，依赖外部，仅监控打点）分开管理，避免验收归属混淆。
- **检索**：FTS5 + 向量索引均在 SQLite 内，无独立服务；分块增量更新，避免全量重建。
- **AI 首 token**：SSE 流式 + 连接复用/预热；明确超时与重试。
- **音频链路**：16kHz 单声道、20ms 帧，VAD 分段后流式发送，减少静音流量与延迟。
- **内存**：本地 ASR 与嵌入模型按需加载/卸载，空闲时不驻留；迷你模式复用主窗口 WebView（不创建第二 WebView），无额外常驻内存。
- **转写落库（P0）**：转写 final 段实时写入 SQLite，崩溃/断电不丢会话记录；P1 仅补浏览/导出 UI。
- **日志**：Rust `tracing` 分级记录，脱敏（不落 API Key/转写正文），关键路径采样。
- **页面切换响应（NFR-17）**：Tauri 命令统一异步执行（`#[tauri::command(async)]`），重阻塞命令落 `tauri::async_runtime::spawn_blocking`，设备枚举带 TTL 缓存，避免切页瞬间的数据库 / 设备 / 钥匙链操作占用界面主线程；前端切页用 `useTransition` 分流，并对重型渲染（Markdown 预览、笔记列表、群组树）做记忆化。详见 6.15。
- **测试**：核心模块单测（jieba 分词/分块/融合排序）+ PCM 文件回放集成测试。

## 10. 隐私与安全

- 默认本地存储；云端 ASR 由首次启动向导显式选择开启，设置页可随时切换为本地模式。

## 15. 前端 UI 视觉规范与设计令牌（2026-09-27）

工程约定：每个功能等于一项任务，改动须「实现 → 测试 → 测试通过 → git 提交」，本文档与《需求分析》同步更新。

### 15.1 圆角：单一事实来源
圆角一律通过 `tailwind.config.js` 的 `borderRadius` 令牌消费，组件只写语义档位类名，**禁止任意值**（`rounded-[…]`）：

| 层级 | 类名 | 令牌值 | 典型对象 |
|---|---|---|---|
| 页面级大卡 / 空态卡 / 全屏拖拽区 | `rounded-2xl` | 16px | 向导主卡、知识库空态卡、拖拽导入遮罩卡 |
| 卡片 / 面板 / 分区 / 抽屉 / 迷你外壳 | `rounded-xl` | 12px | 各设置分区、面试面板、`glass` 卡片、MiniView、会话列表项 |
| 嵌套次级块 / 提示条 / 代码块 / 图片 | `rounded-md` | 8px | 卡片内信息块、success/danger/warning 提示条、引用来源条目、markdown 代码块 |
| 控件（按钮 / 输入框 / 下拉 / 分段控件 / 列表项） | `rounded-lg` | 10px | 表单控件、各 `FIELD` 常量、分段器外层与分段项容器 |
| 小件（图标按钮 / 徽章 / 标签 / 行内 code） | `rounded`（= `rounded-sm`） | 6px | 标题栏窗口按钮、chip、版本徽章、群组树行内重命名输入框 |
| 胶囊 / 状态圆点 / 进度条 / 头像 | `rounded-full` | 9999px | 状态胶囊、状态圆点、下载与向导进度条 |

约束：**外层圆角恒大于等于内层**（12 > 10 > 8 > 6），禁止出现「卡片很圆、内部按钮很尖」或内层大于外层的倒挂。

### 15.2 阴影：四档令牌
| 令牌 | 值 | 用途 |
|---|---|---|
| `shadow-card` | 双层柔和阴影（1px 近阴影 + 24px 扩散） | 全部卡片 / 面板 / 分区；紧凑工具条与状态条不使用阴影 |
| `shadow-card-hover` | 略强于 `card` | 卡片悬停增强（预留） |
| `shadow-popover` | 40px 大扩散 | 浮层 / 弹窗（预留） |
| `shadow-brand` | 品牌色发光 | Logo 与面板页头图标块（替代原先散落的 `shadow-lg shadow-primary/25`） |

### 15.3 描边、交互态与间距节奏
- **描边**：卡片与结构分隔线统一 `border-ghost/[0.06]`；控件统一 `border-ghost/10`；语义色边框保留（`border-danger/30`、`border-warning/30`、`border-primary/40` 等）。`ghost` 为 ST-13 引入的双主题叠加令牌：深色 `rgb(255 255 255)`、浅色 `rgb(15 20 32)`，故原 `border-white/[0.06]` / `border-white/10` 写法已全部替换（浅色下叠白会丢失描边）。
- **悬停**：幽灵态统一 `hover:bg-ghost/[0.06]`；主行动统一 `hover:bg-primary/25`；危险行动 `hover:bg-danger/25`；过渡统一 `transition-colors`（150–200ms）。
- **双主题**：上述描边/悬停/文字色/背景色一律通过 6.14 定义的 CSS 变量令牌取值，浅色与深色共用同一套类名，切换主题不改动组件结构。
- **键盘聚焦**：`src/index.css` 提供 `.focus-ring` 工具类（`focus-visible` 2px 品牌色光环 + 1px offset），应用于全部按钮、复选框与输入控件；输入框同时保留 `focus:border-primary/50`。该工具类为唯一聚焦态来源，避免逐组件重复写法。
- **内边距节奏**：卡片常规 `p-4`、密集区 `p-3`、页面级大卡 `p-6`；块间距统一 12 / 16 / 24 的 4px 网格，消除 `px-10 py-12`、`px-14 py-10` 一类散值。
- **非 Tailwind 段落**：滚动条 thumb 6px；`.markdown-body` 行内 code 6px、代码块与图片 8px；`.cm-editor` 保持无圆角。

### 15.4 覆盖范围与不改动项
- **覆盖**：自定义标题栏与侧边导航（`App.tsx`）、知识库页、面试辅助页（含 `MiniView` / `ShortcutBar` / `DemoCard`）、会话历史页、设置页 9 个分区组件、首次启动向导，以及 `index.css` 内的滚动条与 Markdown 样式。
- **不改**：窗口外框仍由系统绘制圆角（`tauri.conf.json` 保持 `decorations: false` / `transparent: false`）；字体、页面布局结构、交互逻辑与文案不变；深色配色取值不变（作为 ST-13 回归基线）；不抽取共享 React 组件，仅新增纯 CSS 工具类与令牌。

### 15.5 面试辅助页布局（IA-17，2026-09-28）
页面按「左侧输入链路 / 右侧结果输出」分区，只调整容器类名与面板挂载位置，不动组件内部结构、store 与事件链路。

| 位置 | 容器类名 | 面板（自上而下） |
|---|---|---|
| 两列外层 | `flex min-h-0 flex-1 gap-4 overflow-hidden p-4` | — |
| 左列 | `flex min-h-0 w-[45%] shrink-0 flex-col gap-4 overflow-y-auto [&>*]:shrink-0` | `DemoCard`（仅 `!running`）→ `AudioCapturePanel` → `TranscriptPanel` |
| 右列 | `flex min-h-0 min-w-0 flex-1 flex-col gap-4 overflow-y-auto [&>*]:shrink-0` | `ShortcutBar` → `QuestionPanel` → `AnswerPanel` |

- **统一约定（两列通用，勿回退）**：面试辅助页两列都是「按内容排布 + 整体滚动」的内容列，直接子面板必须带 `shrink-0`（`[&>*]:shrink-0`），否则内容超出可视高度时会被压扁并溢出到下一个面板（视觉重叠）。**需要伸展的面板用 `grow`**（当前仅 `TranscriptPanel`，其根容器为 `shrink-0 grow`，列表为 `min-h-[140px] flex-1 overflow-y-auto` → 占满左列剩余高度且在面板内部滚动）。
- **左列宽度用比例而非固定像素**：`w-[45%] shrink-0` + 右列 `flex-1 min-w-0`。**禁止**用 `flex-1` 表达左列宽度（`flex: 1 1 0%` 与 `shrink-0` 语义冲突），也不再使用 `w-80` / `w-96` 等固定宽度。
- **兜底行为**：窗口过矮时左列整体滚动（`overflow-y-auto`），断言面板不被裁切；窗口很窄时右列先让位（`min-w-0`），左列不塌陷。
- 文案一致性：`AudioCapturePanel` 的引导语句随位置改为「开始转写请在**下方**『实时转写』中」（裸 JSX 文本，不进 i18n 词典）。
- **面板内部结构（2026-09-29 变更，勿回退）**：`QuestionPanel` 只负责「问题识别」本身（问题文本 / 置信度徽标 / 命中信号 chips / 近期问题列表 / 手动识别按钮），**不再罗列召回片段**（原「知识库参考」区块连同片段数、无命中查询词空态一并删除）。召回结果 `interviewStore.sources` 的唯一消费方是 `AnswerPanel` 的「引用来源」（IA-09）与迷你模式「引用：」，因此 `recallSources(sessionId, currentQaId)` 的触发 effect 挂在 **`AnswerPanel`**（依赖 `[sessionId, currentQaId, recallSources]`，条件 `if (sessionId && currentQaId)`）。注意 `applyAnswerPush` 不写 `sources`：把触发点留在别处会让「引用来源」退化为仅标题的 `persistedSources` 兜底。
- 回归：`AudioCapturePanel.test.tsx`（断言 `/不产生转写文本/`、`/开始转写/`，改文案后仍通过）+ 新增 `pages/__tests__/InterviewPage.test.tsx`（桩化 6 个子面板，断言两列归属与顺序、`running` 时不渲染 `DemoCard`）；`npm run verify` 通过。
- 回归（IA-07 变更，2026-09-29）：`QuestionPanel.test.tsx` 新增「不再展示知识库召回相关内容」断言（`知识库参考` / `条片段` / `未召回到相关内容` 均不出现），`AnswerPanel.test.tsx` 接手「识别到新问题时自动召回知识库片段」用例（`recallSources` 以 `("s-1", "q1")` 被调用）；`npm run verify` 通过。
