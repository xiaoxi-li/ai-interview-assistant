# AI 面试助手桌面客户端 — 技术方案

> 版本：v0.2（审核修订版） · 状态：草案 · 目标平台：Windows 10/11、macOS 13+

## 1. 项目概述

### 1.1 定位
AI 面试助手桌面客户端，为求职者在远程面试场景中提供两大核心能力：

1. **知识库**：Markdown 笔记的导入、编辑、维护、群组管理，以及全文/语义检索。
2. **面试辅助**：实时捕获面试官语音 → 流式转文字 → 检索知识库 → 结合 AI 生成回答。

### 1.2 设计原则
| 原则 | 说明 |
|---|---|
| 本地优先 | 笔记、检索、会话数据默认本地存储，知识库离线可用 |
| 低资源占用 | 安装包 < 20MB（不含按需下载的模型，磁盘占用另计）；空闲内存 < 100MB（不含本地 ASR 加载时的模型内存） |
| 低延迟 | 客户端预算：检索 < 200ms、IPC 事件 < 50ms、首帧渲染 < 100ms；端到端目标（依赖外部服务）：ASR < 1s、AI 首 token < 2s |
| 隐私可控 | 云端 ASR 由首次启动向导显式选择，设置页可随时切换云端/本地；API Key 不明文落盘 |
| 双平台一致 | Windows 与 macOS 提供一致体验 |

### 2.4 非功能需求
- **性能（两类指标拆分验收）**：
  - 客户端预算（本地可控、可测试）：安装包 < 20MB（不含模型）；空闲内存 < 100MB；检索 < 200ms；IPC 事件延迟 < 50ms；界面首帧渲染 < 100ms。
  - 端到端目标（依赖外部网络与服务商，仅做监控打点不作为客户端验收）：ASR 端到端 < 1s；AI 首 token < 2s。
- **隐私**：默认本地存储；云端 ASR 由首次启动向导显式选择开启，可随时切换为本地；API Key 不明文落盘。
- **安全**：HTTPS、系统密钥链、本地敏感字段加密。
- **可用性**：知识库离线可用；AI 需联网；云端 ASR 需联网，本地 ASR 需首次下载模型。
- **可维护性**：模块化、Provider 抽象、双平台 CI。
- **测试策略**：Rust 核心模块单元测试（分块/jieba 分词/融合排序可纯本地验证）；音频链路用 PCM 文件回放做集成测试，不依赖真实设备。

## 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | **Tauri 2.x (Rust)** | 系统 WebView + Rust 原生能力，轻量化 |
| 前端 | **React 18 + TypeScript + Vite 5** | 生态成熟，Markdown 编辑器方案多 |
| UI | **shadcn/ui + Tailwind CSS** | 现代、可定制、轻量 |
| 状态管理 | **Zustand** | 轻量，适合实时事件流驱动 |
| 数据存储 | **SQLite（rusqlite）+ FTS5 + sqlite-vec** | 单一数据文件，内嵌全文/向量检索 |
| 中文分词 | **jieba-rs** | FTS5 写入/查询前预分词（unicode61 对中文无效），纯 Rust 无平台负担 |
| 向量检索 | **sqlite-vec** | SQLite 内嵌向量虚拟表，抽象 `VectorStore` trait 便于未来迁移 |
| 嵌入模型 | **ONNX Runtime + 小模型**，Provider 抽象 | 本地优先、零网络延迟、隐私好 |
| 音频 I/O | **cpal + 平台特化**（WASAPI loopback / ScreenCaptureKit） | 跨平台统一抽象，平台差异隔离 |
| VAD / AEC | **silero-vad (ONNX)** / **webrtc-audio-processing**（P1） | 轻量 VAD；AEC 与说话人双流同期 |
| 本地 ASR | **sherpa-onnx**（中文 paraformer） | 隐私可选，按需加载 |
| 云端 ASR | **多服务商 Provider：讯飞 / 阿里 / 腾讯**（各家 WebSocket 协议互不兼容，逐个适配；首期先接讯飞一家，其余 P1 跟进） | 低延迟；凭证独立配置 |
| 云端 AI | HTTP SSE，OpenAI 兼容 Provider | DeepSeek/Qwen/GLM/ChatGPT 统一抽象 |
| 密钥安全 | **keyring crate** | macOS Keychain / Windows Credential Manager |
| 模型分发 | **模型管理器**：按需下载（国内镜像）、SHA256 校验、断点续传 | 安装包 < 20MB 不含模型 |

### 3.1 为何选择 Tauri 而非 Electron
| 维度 | Tauri 2 | Electron |
|---|---|---|
| 原生能力 | Rust 插件（音频/钥匙链/托盘/快捷键） | Node 桥接，较重 |
| 后端语言 | Rust（性能 + 内存安全） | JS/TS |

结论：基于轻量化与原生能力优势选择 Tauri 2。

```
└──────────────┬──────────────────────────────┘

│  │ VAD    │ │多厂商 │ │      │ │          │ │
│  └────────┘ └──────┘ └──────┘ └──────────┘ │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌───────┐ │
│  │Retrieval│ │Knowledge│ │Session │ │Security│ │
│  │FTS5+Vec│ │        │ │        │ │       │ │
│  └────────┘ └────────┘ └────────┘ └───────┘ │
│  ┌──────────────────────────────────────┐   │

│  └──────────────────────────────────────┘   │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│                 存储层                       │
│   SQLite（FTS5 + 向量）· 系统钥匙链           │
└─────────────────────────────────────────────┘
```

**总体策略**：Rust 侧承担所有重活（音频、VAD、ASR、检索、AI、存储、模型管理），前端只负责展示与交互。实时链路（音频 → ASR → 检索 → AI）全部在 Rust 侧完成，通过 Tauri Event 将 partial/final 转写、流式 token 推送到 WebView，避免跨进程多次序列化，保证低延迟。

### 4.2 核心数据流
```
音频设备 → AudioCapture（双流）→ VAD 分段 → ASR Provider（流式）
  → 转写事件推送前端 + 转写落库（P0）
  → 问题识别触发 → 检索服务（jieba+FTS5 + 向量 + 融合排序）
  → AI Provider（SSE 流式）→ token 事件推送前端 → 会话服务落库
```

## 6. 核心模块设计

### 6.1 音频捕获（audio）
- 定义 `AudioCapture` trait，隔离平台差异：
  - **Windows**：系统音频走 WASAPI loopback，麦克风走 WASAPI capture。
  - **macOS**：系统音频走 ScreenCaptureKit（需屏幕录制授权，这是 macOS 13+ 要求的根源），麦克风走 AVAudioEngine。
- 麦克风与系统音频作为两条**独立流**，天然实现「我/面试官」通道近似区分。

```rust
pub trait AudioCapture: Send {
    fn start(&mut self, device: &AudioDevice) -> Result<()>;
    fn stop(&mut self) -> Result<()>;
    fn subscribe(&self) -> mpsc::Receiver<AudioChunk>; // 16kHz PCM 帧流
}
```

### 6.2 VAD / 回声消除
- **VAD（P0）**：silero-vad（ONNX）静音过滤 + 自动分段，20ms 帧。
- **AEC（P1）**：P0 阶段麦克风流尚无 ASR 消费方（说话人双流在 P1），AEC 无实际收益，故降级与 IA-05 同期交付。实现采用 webrtc-audio-processing；若平台系统 AEC 可用则优先系统 AEC，降低 CPU 占用。

### 6.3 ASR（asr）
- **多服务商抽象**：`AsrProvider` trait + 讯飞/阿里/腾讯逐个适配（各家 WebSocket 流式协议互不兼容，AppID/凭证独立配置，存入钥匙链）。**首期先接讯飞一家**跑通链路，阿里/腾讯在 P1 跟进。
- **模式选择**：云端/本地由**首次启动向导显式选择**（满足隐私条款「云端 ASR 需明确开启」），设置页（ST-04）可随时切换。
- **本地 ASR**：sherpa-onnx（中文 paraformer），按需加载作为隐私选项，空闲时卸载。
- 输出 partial / final 事件，携带通道标记说话人。

```rust
pub trait AsrProvider: Send {
    fn connect(&mut self, cfg: AsrConfig) -> Result<()>;
    fn feed(&mut self, chunk: AudioChunk) -> Result<()>;        // 流式喂入
    fn events(&self) -> mpsc::Receiver<AsrEvent>;               // partial/final
}
```

### 6.4 AI（ai）
- 统一 OpenAI 兼容 Provider：DeepSeek / Qwen / GLM / ChatGPT 共用同一协议，可插拔适配。
- SSE 流式输出，连接复用/预热，目标首 token < 2s，含超时与重试策略。
- 连接测试走轻量模型列表接口。

### 6.5 Embedding（embedding）
- `EmbeddingProvider` trait（本地 ONNX / 云端 API）。
- 默认本地小模型嵌入，保证检索 < 200ms 且知识库离线可用。

### 6.6 检索（retrieval）
- **中文分词（关键）**：FTS5 默认 unicode61 分词器把连续中文当作整句 token，中文检索基本无效。方案：**jieba-rs 预分词**——写入 FTS 前分词并以空格拼接存储，查询词同样预处理，BM25 打分正常工作。
- **召回**：FTS5 BM25 召回 + 向量余弦召回。
- **融合排序**：P0 先用**固定权重融合**（两路得分归一化后加权相加，快速闭环）；P1 升级为标准 **RRF** 并开放参数。
- 笔记分块默认 512 token、重叠 50（参数可配置），块与笔记/标签/群组关联。

### 6.7 安全（security）
- keyring crate：API Key 与 ASR 服务商凭证存 macOS Keychain / Windows Credential Manager。
- 本地数据加密采用**字段级加密**：仅加密敏感字段（转写正文、问答内容用 AES-GCM），避免 SQLCipher 与 sqlite-vec 扩展的兼容性风险；备选 OS 级保护（Windows DPAPI / macOS 数据保护）。

### 6.8 Provider 抽象模式
```rust
pub trait Provider {
    type Config;
    type Output;
    fn connect(&mut self, cfg: Self::Config) -> Result<()>;
    fn test(&self) -> Result<()>;
    fn stream(&mut self, input: Input) -> Pin<Box<dyn Stream<Item = Result<Self::Output>>>>;
}
```

### 6.9 迷你模式（Mini View）
- 前端页面右上角提供「缩小」按钮，切换至**独立迷你小窗**（无边框、置顶、可拖动），体验类似桌面便签。
- 迷你窗仅展示：当前识别到的面试官问题 + AI 流式回复（含引用来源标签）。
- **实现方式**：独立第二 WebView 窗口（`mini` window，默认不创建，点击时懒创建并隐藏主窗；恢复时反向操作）。
- **内存取舍**：迷你窗激活时约 +40–60MB 内存（第二 WebView）；因迷你窗与主窗不同时展示内容，主窗可在迷你期间最小化至托盘以对冲；该开销在面试激活态可接受，空闲态不受影响。
- 配合窗口置顶与全局快捷键使用。

### 6.10 模型管理器（models）
- 解决「安装包 < 20MB」与「模型体积」的矛盾：模型不打包，**按需下载**。
- 能力：国内镜像源下载、SHA256 完整性校验、断点续传、进度事件推送前端、缓存于应用数据目录、版本更新与删除（ST-10 界面）。
- 托管模型：嵌入模型（~90MB）、silero-vad（~2MB）、本地 ASR 模型（~200MB，仅在选择本地模式时下载）。

### 6.11 首次启动向导（Onboarding）
四步引导，解决「权限门槛 + 隐私条款 + 模型分发」三个首次体验问题：
1. **权限引导**：macOS 麦克风 + 屏幕录制授权（Windows 无系统音频授权门槛）；不授权则明确告知功能受限范围。
2. **ASR 模式显式选择**：云端（低延迟，需服务商凭证、音频上传）vs 本地（隐私，需下载模型）——满足隐私条款的「明确开启」。
3. **模型下载**：按所选模式下载必需模型，展示进度。
4. **AI 平台配置**：选择平台、填入 API Key（存钥匙链）、连接测试。

## 7. 数据模型

### 7.1 核心表结构
| 表 | 说明 | 关键字段 |
|---|---|---|
| notes | 笔记 | id、title、content、group_id、created_at、updated_at、is_deleted |
| groups | 群组 | id、name、parent_id、order |
| tags | 标签 | id、name、color |
| note_tags | 笔记-标签关联 | note_id、tag_id |
| note_versions | 版本历史 | id、note_id、content、version、created_at |
| chunks | 笔记分块 | id、note_id、content、position |
| fts_index | FTS5 虚拟表 | title、content、tags（jieba 预分词后存储） |
| vec_chunks | 向量虚拟表（sqlite-vec） | chunk_id、embedding |
| sessions | 面试会话 | id、title、started_at、ended_at |
| transcript_segments | 转写片段 | id、session_id、speaker、text（加密）、is_final、timestamp |
| qa_pairs | 问答记录 | id、session_id、question、answer（加密）、sources、timestamp |
| settings | 配置 | key、value（JSON） |

### 7.2 检索索引
- **FTS5 虚拟表**：notes(title, content, tags) 经 jieba-rs 分词后建立全文索引。
- **向量虚拟表**：sqlite-vec 存储 chunk 的 embedding，余弦相似度检索；抽象 `VectorStore` trait。

## 8. 关键技术决策与权衡

| 决策点 | 方案 | 权衡说明 |
|---|---|---|
| 跨平台音频 | AudioCapture trait + 平台特化 | 隔离 WASAPI / ScreenCaptureKit 差异 |
| 说话人区分 | P1 用「音频通道近似」（麦克风=我，系统音频=面试官） | 零额外成本；真实 diarization 延后 |
| 云端 ASR | 多服务商 Provider（首期讯飞，阿里/腾讯 P1）+ 本地可选 | 各家协议互不兼容故逐个适配；云端延迟低 |
| ASR 模式选择 | 首次向导显式选择 + 设置页可切换 | 同时满足隐私条款与低延迟需求 |
| 中文检索 | jieba-rs 预分词 | FTS5 默认分词对中文无效，必须预处理 |
| 混合检索 | P0 固定权重融合 → P1 RRF | P0 尽快闭环，P1 精细化 |
| 迷你模式 | 独立无边框置顶小窗（懒创建） | 便签式体验最优；接受激活态 +40–60MB 内存 |
| 模型分发 | 按需下载 + 校验 + 断点续传 | 安装包 < 20MB 口径不含模型 |
| AEC 时机 | P1 与说话人双流同期 | P0 麦克风流无 ASR 消费方，AEC 无收益 |
| 本地加密 | 字段级 AES-GCM | 规避 SQLCipher 与 sqlite-vec 兼容风险 |
| 密钥安全 | keyring 存系统钥匙链 | 不明文落盘 |

## 9. 性能与优化策略

- **指标拆分**：客户端预算（检索/IPC/渲染，本地可控可验收）与端到端目标（ASR/AI 首 token，依赖外部，仅监控打点）分开管理，避免验收归属混淆。
- **检索**：FTS5 + 向量索引均在 SQLite 内，无独立服务；分块增量更新，避免全量重建。
- **AI 首 token**：SSE 流式 + 连接复用/预热；明确超时与重试。
- **音频链路**：16kHz 单声道、20ms 帧，VAD 分段后流式发送，减少静音流量与延迟。
- **内存**：本地 ASR 与嵌入模型按需加载/卸载，空闲时不驻留；迷你窗懒创建、关闭即销毁 WebView。
- **转写落库（P0）**：转写 final 段实时写入 SQLite，崩溃/断电不丢会话记录；P1 仅补浏览/导出 UI。
- **日志**：Rust `tracing` 分级记录，脱敏（不落 API Key/转写正文），关键路径采样。
- **测试**：核心模块单测（jieba 分词/分块/融合排序）+ PCM 文件回放集成测试。

## 10. 隐私与安全

- 默认本地存储；云端 ASR 由首次启动向导显式选择开启，设置页可随时切换为本地模式。
- API Key 与 ASR 服务商凭证存系统钥匙链，不明文落盘。
- HTTPS 传输；本地敏感字段（转写/问答内容）可选 AES-GCM 加密。
- 隐私设置提供「清除数据」能力。
